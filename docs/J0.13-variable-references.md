# J0.13 — Références de variables scalaires tokenisées CPC

**État : En revue Pilotage.** Décodeur C99 natif indépendant du matériel pour le **Locomotive BASIC 1.1 de l'Amstrad CPC 6128**. Aucune exécution de Z80. Les vecteurs de test ci-dessous sont construits à partir de la ROM ; **aucun n'est une capture CPC indépendante**.

## 1. Format et étude ROM

**[C] E075–E0A8** : FF9C parcourt un identifiant ; E0D1 reconnaît les suffixes ; E081/E085/E08B émet le marqueur, E08E–E093 émet les deux octets de cache initialement nuls, E097–E0A4 recopie les octets du nom ; **E1B5–E1BA** positionne le bit 7 du dernier octet. Format considéré :
- octet 0 : marqueur de variable ;
- octets 1 et 2 : cache/offset historiques CPC, **ordre little-endian**, conservés séparément et sans interprétation ;
- octets 3 à 3+N-1 : N caractères de nom ; le dernier octet a son bit 7 positionné.

**[C] D931–D946** lit les deux octets suivants et, suivant le contenu du cache, parcourt le nom jusqu'au bit 7. **[C] D96C–D990** consulte les types implicites selon l'initiale et peut modifier le marqueur en mémoire CPC ; **D9AF–D9C8** traite les familles codées 02/03/04 et 0B/0C/0D. Ces chemins ne donnent aucune autorisation de traduire un cache en pointeur ESP32.

| Marqueur | Famille renvoyée | Type explicite |
|---|---|---|
| 02 | BVR_FAMILY_EXPLICIT | BVR_TYPE_INTEGER (%) **[C]** |
| 03 | BVR_FAMILY_EXPLICIT | BVR_TYPE_STRING ($) **[C]** |
| 04 | BVR_FAMILY_EXPLICIT | BVR_TYPE_REAL (!) **[C]** |
| 0B, 0C, 0D | BVR_FAMILY_UNSUFFIXED_OR_RESOLVED | BVR_TYPE_UNDETERMINED **[V]** |

**[V/B]** Ne pas déduire de ce tableau un type stable et universel des trois marqueurs 0B/0C/0D. La réécriture possible selon DEFINT/DEFREAL/DEFSTR, les variantes exactes émises, la conservation des caches et leurs états avant/après RUN exigent des observations CPC indépendantes.

## 2. Validation lexicale

**[C] FF92–FFB3** : première lettre ASCII (A–Z ou a–z, après normalisation de comparaison) ; caractères suivants autorisés par FF9C : lettre, chiffre 0–9 ou point. Le décodeur masque le bit 7 *avant* de contrôler chaque caractère ; ainsi C1 est le dernier octet du nom « A », et E9 est le dernier octet d'un « i » ASCII, pas une lettre accentuée. Le module ne change pas la casse et ne réécrit jamais le nom.

**[C] D991–D9A4** : le compteur de copie autorise au plus **40 octets de nom**, erreur avant la 41e copie. Le décodeur impose 1 à 40 octets avec un bit 7 terminal ; il retourne TRUNCATED si les 40 caractères sont disponibles sans terminaison, mais LIMIT_EXCEEDED si un 41e octet serait nécessaire. Un nom vide, ou commençant par chiffre/point, est rejeté.

**[V]** Le comportement complet des graphies complexes (par exemple point final/doubles points ou autres contextes lexicaux) nécessite une validation sur CPC. Accepter exactement la classe FF9C pour les suites n'est **pas** une revendication de fidélité de toute la grammaire BASIC.

## 3. API et garanties

L'API portable est : **BVRStatus bvr_decode(const uint8_t *source, size_t source_length, size_t offset, BasicVariableRef *result)**.

Le résultat contient exclusivement : marker, family, explicit_type, cache_low, cache_high, reference_offset, name_offset, name_length et consumed. Les offsets sont relatifs à *source*, jamais à l'espace RAM CPC. Le résultat ne conserve **aucun pointeur** ; le nom n'est accessible qu'en relisant le buffer de l'appelant avec (name_offset, name_length). consumed inclut le marqueur, les deux octets de cache et le nom, sans avaler les octets suivants.

- **[C, code]** Aucun malloc/free, aucune variable globale mutable, aucune dépendance matérielle, aucune résolution dans la table des symboles, aucun appel à DEFINT/DEFREAL/DEFSTR.
- **[C, code]** Vérification des soustractions de longueur avant tout accès ; aucune addition d'offset non prouvée sûre. Lecture de 40 caractères au plus. Les octets du programme et du cache sont exclusivement lus.
- **[C, code]** Un seul commit de résultat après validation complète. **Tous les échecs laissent *result inchangé octet par octet**, et ne modifient jamais source.
- **[C, code]** L'API refuse tout chevauchement entre les source_length octets d'entrée et l'objet résultat. Test des intervalles via uintptr_t et différences d'adresses, sans somme de fins d'intervalles. **[D]** La garantie de détection est ciblée sur les représentations Linux et Xtensa/ESP32 ; des extents mensongers ou objets invalides sont hors contrat.

| Statut | Signification |
|---|---|
| BVR_OK | Référence valide |
| BVR_INVALID_ARGUMENT | Pointeur nul ou offset >= longueur |
| BVR_UNRECOGNIZED_MARKER | Marqueur différent de 02,03,04,0B,0C,0D |
| BVR_MALFORMED | Caractère de nom invalide |
| BVR_TRUNCATED | Cache, nom ou bit terminal absent dans la longueur disponible |
| BVR_LIMIT_EXCEEDED | Plus de 40 caractères avant terminaison |
| BVR_OVERLAPPING_MEMORY | Le résultat chevauche la source |

**[B]** Le cache historique à deux octets **n'est ni un pointeur hôte ni un identifiant stable**, même lorsqu'il est non nul. Toute résolution future devra utiliser un cache séparé et invalidable. J0.13 n'introduit aucun changement au format basic_program, au tokenizer, à LIST, RUN ou l'exécuteur.

## 4. Vecteurs binaires synthétiques et couverture

| Octets hexadécimaux | Résultat attendu |
|---|---|
| 02 00 00 C1 | A, type entier explicite, name_length=1, consumed=4 |
| 03 34 12 6D 69 78 C5 | mixE, chaîne explicite, cache brut 34 12, longueur=4, consumed=7 |
| 04 FF 01 E1 | a, réel explicite, cache brut FF 01, longueur=1 |
| 02 12 34 41 2E 32 E2 | A.2b, nom pointé, longueur=4, consumed=7 |
| 0B/0C/0D xx yy 61 62 C3 | abc, famille implicite/résolue, type indéterminé |
| 58 04 78 56 61 39 AE 51 (offset 1) | a9., consumed=6, le Q final est préservé |

**[C, tests]** La dixième suite CTest, *basic_variable_ref*, vérifie statuts **et** marqueur, famille, type, deux octets cache, offsets, longueurs et octets réellement consommés ; variations de casse et de point ; trois marqueurs implicites ; cache zéro/non zéro ; entrée au milieu d'un buffer. Elle vérifie aussi les absences et troncatures de champ, le bit 7 manquant, les caractères interdits (chiffre initial, point initial, underscore, espace, NUL masqué), l'offset initial hors bornes y compris SIZE_MAX, la longueur 40, le dépassement à 41, l'atomicité du résultat en erreur, l'immuabilité source et le chevauchement. Aucun de ces vecteurs n'est qualifié de « golden dump CPC ».

Validation Linux (dans deux dossiers séparés) :
1. cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug ; cmake --build build ; ctest --test-dir build --output-on-failure
2. cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DBP_SANITIZERS=ON ; cmake --build build-asan ; ctest --test-dir build-asan --output-on-failure

Le workflow CI teste les deux configurations. **[V]** La validation de références sur CPC 6128 réel ou émulateur servant d'oracle reste à faire.
