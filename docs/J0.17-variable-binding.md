# J0.17 — Binding natif des références scalaires explicites CPC

**État :** acceptée et fusionnée par Pilotage via PR #17 (squash `fd6e6d16`, 25 octobre 2026, heure de Paris). **Cible :** Locomotive BASIC 1.1, Amstrad CPC 6128, réimplémentation native C99, sans Z80.

## Périmètre

Le module `core/basic_variable_binding.h/.c` est un pont **purement fonctionnel** entre le flux tokenisé et les composants scalaires déjà acceptés :
1. `bvr_decode` (J0.13) valide une référence à l'offset demandé dans un buffer de longueur explicite.
2. Seule la famille explicite `02/03/04` est acceptée ; `0B/0C/0D` retourne `BVB_UNSUPPORTED_FAMILY`, même avec un cache non nul.
3. `bvt_canonicalize` et `bvt_build_key` (J0.14) produisent la clé canonique sans supprimer ni tronquer le nom complet.
4. `bvs_get` (J0.15) copie une valeur **déjà présente** depuis un magasin fourni par l'appelant, sans aucune création.

Le cache CPC de deux octets est ignoré pour la résolution, indépendamment de sa valeur, et n'est jamais écrit ou interprété comme pointeur hôte. Seule la clé convertit les lettres en majuscules ; les octets du programme restent identiques.

## Types et API

| Marqueur en programme | Suffixe | `BasicVariableType` dans la clé | Valeur |
|---|---|---|---|
| `02` | `%` | `BVT_INTEGER = 02` | `int16_t` |
| `03` | `$` | `BVT_STRING = 03` | `BasicStringValue` (vide uniquement dans J0.15) |
| `04` | `!` | `BVT_REAL = 05` | cinq octets `real5` bruts |

```c
BVBStatus bvb_resolve_explicit(const uint8_t *source, size_t source_length,
                               size_t offset, BasicVariableKey *out_key,
                               size_t *out_consumed);

BVBStatus bvb_read_explicit(const uint8_t *source, size_t source_length,
                            size_t offset, const BasicVariableStore *store,
                            BasicVariableKey *out_key, size_t *out_consumed,
                            BasicVariableValue *out_value);
```

La longueur consommée compte **marqueur + 2 octets cache + 1 à 40 octets de nom**, soit 4 à 43 octets, et non la longueur de la ligne ou le nombre d'octets précédant l'offset. L'offset peut être non nul (notamment après `PRINT` ou un espace). Les noms sont limités à 40 caractères ASCII CPC validés par J0.13, avec bit 7 sur le dernier octet. L'identité de la clé porte sur le nom complet et le type effectif.

La seconde API renvoie la clé, la longueur et la valeur **uniquement quand le magasin contient cette clé**. Un magasin vide ou une clé absente renvoie `BVB_NOT_FOUND` : les sorties restent inchangées, les entrées et le compteur ne bougent pas. Il n'existe pas d'initialisation implicite dans ce module ; le comportement CPC de première lecture devra faire l'objet d'une validation séparée.

## Statuts internes et atomicité

| Statut | Sens |
|---|---|
| `BVB_OK` | Résolution/lecture réussie |
| `BVB_NOT_FOUND` | Clé valide absente du magasin ; aucune création |
| `BVB_INVALID_ARGUMENT` | Pointeur nul, offset hors source |
| `BVB_UNRECOGNIZED_MARKER` | Marqueur non décodable par J0.13 |
| `BVB_UNSUPPORTED_FAMILY` | Famille `0B/0C/0D`, intentionnellement hors périmètre |
| `BVB_MALFORMED` | Nom invalide ou référence malformée |
| `BVB_TRUNCATED` | Champ obligatoire/terminateur absent dans le flux |
| `BVB_LIMIT_EXCEEDED` | Nom excédant 40 caractères |
| `BVB_OVERLAPPING_MEMORY` | Chevauchement de buffers, sorties, magasin ou tableau d'entrées |
| `BVB_INVALID_REFERENCE` | Incohérence interne signalée par J0.14 |
| `BVB_INVALID_STORE` | Magasin invalide ou rejet de validation J0.15 hors absence/chevauchement |

Ces statuts ne correspondent **pas** aux codes d'erreurs du BASIC historique. Les entrées sont des objets valides, accessibles sur les étendues déclarées, disjoints comme documenté dans `basic_variable_binding.h`. Les vérifications de plages utilisent `uintptr_t` et la soustraction, conformément à J0.13–J0.15 ; sur les cibles prévues (Linux et ESP32), cette représentation est disponible. Un pointeur arbitraire invalide ou une fausse taille d'allocation ne sont pas détectables en C99. Les entrées/sorties aliasées, même partiellement, sont rejetées avant écriture. Les métadonnées structurantes du magasin sont contrôlées pour borner les vérifications de chevauchement ; **J0.15 reste l'autorité** de validation des entrées actives.

La clé et la longueur intermédiaires ainsi que la valeur lue sont temporaires et allouées sur la **pile** de l'appel : aucun `malloc`, état global mutable, adresse de cache hôte, modification d'image BASIC, mutation d'entrée ni donnée conservée entre appels. Les sorties sont copiées uniquement après validation complète, y compris la recherche.

## Empreinte mémoire

Ce jalon ne définit **aucune nouvelle structure persistante**, ni registre de variables, ni nouveau buffer alloué. La clé J0.14 reste un objet de 42 octets et `BasicVariableValue` de 12 octets (mesure GCC x86_64 documentée dans J0.15). Le binding utilise des temporaires sur la pile (référence J0.13, nom canonique, clé, compteur, valeur) : coût transitoire borné O(1), indépendant du nombre de variables ; deux décodages bornés de 40 octets sont effectués par résolution, car J0.14 encapsule lui-même J0.13.

Le magasin conserve les budgets J0.15 : avec 64 entrées, **3 608 octets sur x86_64**, et environ **3 596 octets théoriques sur ESP32** (non mesurés sur Xtensa). Le binding ne change pas ces budgets ; la taille de pile maximale exacte exige une mesure ciblée après compilation croisée. Le temps d'accès à une valeur déjà stockée dépend de la recherche linéaire O(n) de J0.15.

## Tests et limites

La **14e suite CTest** `basic_variable_binding` teste la résolution en décalage non nul après PRINT, le mapping REAL, la normalisation de casse, les collisions de noms et de types, les 40 caractères, les caches non nuls, la restitution INT16/REAL5/chaîne vide, le statut d'absence atomique, le refus de `0B/0C/0D`, les troncatures et invalidités, les aliasages et l'immuabilité du flux et du magasin.

Commandes de reproduction :
```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DBP_SANITIZERS=OFF
cmake --build build --parallel
ctest --test-dir build --output-on-failure

cmake -S . -B build-asan -DCMAKE_BUILD_TYPE=Debug -DBP_SANITIZERS=ON
cmake --build build-asan --parallel
ctest --test-dir build-asan --output-on-failure
```

Les résultats standard et ASan/UBSan du dernier HEAD sont à vérifier dans les jobs GitHub Actions de la PR avant acceptation Pilotage.

**Exclus :** LET/affectations, PRINT évalué, expressions, DEF*, résolution `0B/0C/0D`, initialisation implicite, conversion/arithmétique REAL5, chaînes non vides, HAL et CYD. Comme dans J0.13–J0.16, les vecteurs internes synthétiques ne constituent pas une preuve de fidélité binaire indépendante au CPC 6128.
