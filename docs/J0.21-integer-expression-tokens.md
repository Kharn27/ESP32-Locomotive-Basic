# J0.21 — Tokenisation et LIST d'une expression INTEGER simple

**État : livré, en revue Pilotage.** Branche `feat/j0-21-integer-expression-tokens`, depuis `main` après J0.20 / PR #22 et synchronisation documentaire / PR #23.

## Périmètre : représentation, pas évaluation

Le sous-ensemble C99 accepte l'affectation INTEGER explicite destination `%` suivie soit d'une constante 0..255 (J0.18/J0.19), soit exactement d'une référence INTEGER explicite source `%`, d'un `+` et d'une constante décimale non signée 0..255. Exemples : `B%=A%+3`, `LET B%=A%+3`, `B% = A% + 255`, `B%=B%+1`. Les 1..40 caractères des noms, leur casse et leurs points/chiffres internes sont conservés. Les espaces existant dans le corps tokenisé autour des opérateurs sont reproduits par LIST.

Le programme `10 A%=2 / 20 B%=A%+3 / 30 PRINT B% / 40 END` est saisissable, stockable, listable et exportable. À RUN, la ligne 10 affecte `A%=2`, puis la ligne 20 est refusée avec le diagnostic hôte `BE_UNSUPPORTED`. La valeur 5 **n'est pas calculée**. Une instruction PRINT précédente *sur la même ligne* ne peut pas produire de sortie partielle : les deux passes n'émettent réellement qu'après validation intégrale.

## Preuves du désassemblage

Source primaire : [Locomotive BASIC v1.1, basic.asm](http://cpctech.cpc-live.com/docs/basic.asm). Classification : **[C]** constat direct des instructions/tableaux Z80, **[D]** interprétation ou combinaison de constats, **[V]** à mesurer indépendamment, **[B]** dépendance bloquante.

- **[C]** `E736` table lexicale : `=` → `EF`, `+` → `F4`. `E164–E186` recherche cette table pour la tokenisation d'opérateurs.
- **[C]** `E03A–E0A4` et `E0D1–E0E1` : reconnaissance des variables et typage explicite, INTEGER `%` → `02` ; `E1B5–E1BA` marque la dernière lettre par bit 7. Les deux octets de cache de référence sont documentés depuis J0.13.
- **[C]** `E111–E123` : `0E..17` pour 0..9 ; `19 xx` pour 10..255 dans le chemin d'entier court. `D033–D0CE` traite les références et constantes dans l'expression ; `CF62–CFC3` et `D059` comprennent `F4` dans le chemin opérateur.
- **[D]** Corps canonique natif de `B%=A%+3` : `02 00 00 C2 EF 02 00 00 C1 F4 11`. Découpage : destination B%, égal, source A%, addition, constante 3. Il s'agit d'un vecteur synthétique **dérivé de la ROM**, nullement d'une capture CPC indépendante.
- **[V]** Confirmer sur CPC 6128 l'image exacte de cette combinaison, y compris espaces, caches initiaux et effets des éventuelles optimisations internes ; les captures binaires historiques sont encore absentes. Aucune preuve contraire bloquante identifiée sur le sous-ensemble (**[B]** : aucune pour livrer cette phase restreinte).

## Encodage, LIST et import

`basic_tokenizer` réutilise `bvr_encode_explicit` pour **les deux** références. `basic_listing` réutilise `bvr_decode` pour destination et source. Il n'existe pas de second décodeur CPC. Caches de deux octets indépendants, opaques et non mutés, même si leurs valeurs sont `20` (espace), `EF` (=) ou `F4` (+). LIST n'interprète que les octets situés *hors* références décodées.

LET explicite `A5` et affectation implicite `02` restent distingués. Pour un import `A5 02...` sans séparateur, LIST insère l'espace textuel indispensable entre LET et la variable. Retokeniser normalise les caches à `00 00` ; ce texte reste retokenisable, sans garantir une identité binaire des imports. `bp_import`/`bp_export`, en revanche, conservent bit à bit les images tokenisées.

## Restrictions temporaires et erreurs

Sont **non admis par notre sous-ensemble J0.21**, mais valides dans des contextes du BASIC 1.1 historique : `B%=A%`, `B%=A%+3+4`, `B%=A%-3`, `B%=A%*3`, `B%=A%+C%`, `B%=3+A%`, `B%=A!+3`, `B%=A$+3`, `B%=A%+256`, `B%=A%+-1`, `B%=(A%+3)`. Ni AST, ni opérateurs supplémentaires, ni REAL5/STRING/DEF*, ni évaluation de PRINT, ni matériel ESP32.

Les entrées hors grammaire sont rejetées par `bt_tokenize` sans toucher la sortie ni `written` ; `bl_detokenize` refuse un opérateur manquant, une référence tronquée ou un `19 xx` non canonique, et conserve aussi sortie/`written`. `RUN` reconnaît une expression bien formée, puis retourne `BE_UNSUPPORTED` sans évaluer, sans modifier curseur, magasin, programme, buffer de sortie ou `written`. Les affectations constantes et `PRINT A%` continuent de fonctionner ; GOTO, END et commentaires gardent leurs règles antérieures.

## Vérification

18e suite CTest `integer_expression_tokens` : vecteurs 0/9/10/255, variantes LET/implicite et espaces, noms 40 caractères, casse et auto-référence, caches non nuls dont `20`/`EF`/`F4`, import/export exact, aller-retour LIST, corruptions/troncatures, valeurs `19` non canoniques, limites de capacité et échec RUN atomique. La suite `host_cli` inclut une saisie/LIST/RUN du programme en quatre lignes. Les 17 suites antérieures sont conservées.

Commandes de validation : `cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure`, et `cmake -S . -B build-asan -DBP_SANITIZERS=ON && cmake --build build-asan && ctest --test-dir build-asan --output-on-failure`. La preuve CI précise et le commit final figurent dans la PR.
