# J0.22 — Première évaluation native d'une addition INTEGER

**État : livré, en revue Pilotage.** Branche `feat/j0-22-integer-expression-runtime`, depuis `main` au commit documentaire `f8076286`. Aucune fusion J0.22 autorisée avant revue.

## Contrat fonctionnel

Le moteur C99 peut désormais exécuter une affectation INTEGER autonome avec membre droit exactement `source% + constante`, où `source%` est une référence scalaire INTEGER explicite existante et la constante non signée vaut 0..255. Les affectations littérales de J0.19 restent prises en charge. `LET` explicite/implicite, espaces, noms complets et casse n'ont pas de chemin de traitement spécial. La destination peut être créée ou mise à jour, y compris avec auto-référence. `bvb_read_explicit` assure le décodage et la lecture de la source ; `bvs_assign` assure l'écriture atomique de la destination.

Programme témoin :

```basic
10 A%=2
20 B%=A%+3
30 PRINT B%
40 END
```

Dans le protocole hôte actuel, `PRINT B%` émet exactement les octets `35 0A` (`5` + LF), et le pas qui suit `END` renvoie `BE_END`. Ce format n'est pas celui du CPC complet.

Le décodeur d'addition, privé à `basic_executor.c`, est appelé par les **deux passes** de `be_step`. Il valide et lit une seule référence source, le token d'addition `F4`, et une seule constante canonique (`0E..17` ou `19 xx`, `xx >= 10`). Il ne modifie que ses variables locales et paramètres de sortie lorsque tout est valide. Les caches CPC de deux octets restent opaques, y compris `20`, `EF`, `F4`, et ne sont jamais interprétés comme des pointeurs hôtes ni modifiés.

L'opération utilise `int32_t` pour additionner `int16_t` et `uint8_t`. Les sommes dans l'intervalle [-32768, 32767] sont enregistrées exactement. Hors intervalle, le diagnostic interne **`BE_INTEGER_OVERFLOW`** interrompt la ligne **sans wraparound**. Il ne prétend pas être un code d'erreur CPC. Source absente : `BE_VARIABLE_NOT_FOUND`, sans création implicite. Magasin plein : `BE_STORE_FULL`.

## Atomicité et exclusions

Les deux passes de `be_step` valident avant la seule écriture via `bvs_assign`. L'expression ne produit aucun octet de sortie. Si l'évaluation ou l'affectation échoue, ni destination, ni création partielle, ni curseur, ni programme/cache, ni sortie, ni `written` ne changent. Les lignes antérieures réussies ne sont pas annulées. Les lignes à instructions multiples contenant une affectation restent exclues, y compris quand elle suit un PRINT ou précède une autre instruction. L'API historique sans magasin continue de refuser l'affectation.

Cette livraison n'introduit ni précédence générale, ni expressions imbriquées, ni opérateurs supplémentaires, ni `variable+variable`, ni `constante+variable`, ni REAL5/STRING/DEFINT, ni formatage CPC, ni firmware ESP32.

## Investigation de `basic.asm`

Source primaire : désassemblage fourni de Locomotive BASIC 1.1. **[C]** = constat direct dans le désassemblage, **[D]** = déduction provisoire, **[V]** = validation indépendante manquante, **[B]** = blocage.

- **[C]** Table lexicale `E736` : `+` est tokenisé `F4`; `=` est `EF`. `E111–E123` représente les nombres courts ; `D033–D0CE` consomme les constantes et références tokenisées ; `CF62–CFC3` organise le traitement des opérateurs.
- **[C]** `FD0C–FD1D` dirige l'addition INTEGER vers `DD4A` et, selon l'indicateur de retenue, vers `FF35` (résultat INTEGER) ou `FE78` puis le vecteur firmware `BD7C` (mathématiques réelles). `DD4A–DD51` contient `ADC HL,DE`, `SCF`, `RET PO`, `OR FF` : le chemin dépend du drapeau d'overflow Z80. `FF35` établit le type courant `02` (INTEGER). Les routines de conversion et d'affectation restent à étudier pour fermer la preuve.
- **[D]** La ROM paraît promouvoir certaines additions INTEGER hors intervalle vers la représentation réelle, plutôt que toujours conserver un résultat INTEGER enroulé. Mais le **résultat final d'une affectation à une variable `%`** n'est pas établi par ce seul chemin.
- **[V]** Confirmer sur CPC 6128 Locomotive BASIC 1.1 les cas `32767+1`, `32513+255` et `-32768+255` affectés à `B%`, y compris résultat, éventuelle erreur et conversion, et corroborer avec les chemins `D6BF`, `FECE` et les vecteurs firmware. Vérifier également les variables sources inexistantes, pour lesquelles l'initialisation implicite n'est volontairement pas émulée.
- **[B]** La sémantique historique *exacte* en cas de dépassement reste bloquée pour une déclaration de conformité CPC, **pas** pour ce périmètre natif provisoirement borné. Aucun résultat CPC n'est inventé.

Les vecteurs de tokens employés dans les tests sont **synthétiques, dérivés du désassemblage** et non des captures indépendantes sur CPC.

## Validation attendue

La 19e suite CTest `integer_expression_runtime` vérifie le programme témoin, l'écrasement/auto-référence, 0/9/10/255, les nombres négatifs injectés, INT16_MIN/INT16_MAX, le dépassement, l'absence de source, le magasin plein, les caches CPC non nuls, les références et constantes corrompues, l'intégrité sur erreur, l'API sans magasin et les exclusions multi-instructions. La suite J0.21 `integer_expression_tokens` attend désormais le résultat exécutable et la suite `host_cli` exécute le programme complet jusqu'à END. Les tests antérieurs PRINT/GOTO/END/REM/LIST/NEW restent en place.

Commandes :

```shell
cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure
cmake -S . -B build-asan -DBP_SANITIZERS=ON && cmake --build build-asan && ctest --test-dir build-asan --output-on-failure
```

**Critère de revue Pilotage :** 19/19 suites standard, 19/19 ASan/UBSan, sortie `5\n`, fin normale et atomicité préservée.
