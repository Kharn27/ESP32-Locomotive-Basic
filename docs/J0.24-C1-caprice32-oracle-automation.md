# J0.24-C1 — Automatisation de l'oracle Caprice32 CPC 6128

**Date :** 25 octobre 2026. **Base :** `main` `18af624452cfda20e92371345cf48e858331a53b`. **État :** acquisition à vérifier dans GitHub Actions ; J0.24 historique non clos.

## Architecture / séparation

Un seul gitlink `tests/oracles/caprice32` (mode `160000`) vers l'amont [ColinPitrat/caprice32](https://github.com/ColinPitrat/caprice32), commit figé `8c778bf072a06fb7c23b9cccd179041db7f79a52` du 18 octobre 2026, dont l'existence et l'arbre ont été contrôlés via l'API GitHub. Code Caprice32 sous GPLv2 (voir `COPYING.txt` amont). Aucun code Caprice32 n'est incorporé à `core/`, aucun lien binaire avec le firmware. Le workflow `cpc-oracle.yml` est distinct des 21 CTest Linux.

Les exemples Caprice32 `test/integrated/scripted_operations_timing/test.sh`, `dsk/test.sh`, `bin_load/test.sh` au commit figé pilotent `cap32 -c cap32.cfg -a ...`, `CAP32_DELAY`, `CAP32_SCRNSHOT` et `CAP32_EXIT`. Notre pilote prépare une configuration **isolée par cas** ; saisit d'abord chaque ligne numérotée ; lance `RUN` puis une **sonde d'imprimante distincte** `PRINT #8,<valeur>` ; déclenche une capture PNG et quitte.

## ROM : droits, provenance et limites (importants)

- `debian/copyright` du commit Caprice32 marque `rom/*` **Copyright 1984–1990 Amstrad / License: Commercial / TODO**, et non GPL. Une inclusion dans le dépôt amont n'établit pas une licence libre.
- Historiquement, Cliff Lawson a exposé [la permission Amstrad](https://www.freetimeweb.nl/home/computer/alt/lawsons-amstrad-computer_site/web.ukonline.co.uk/cliff.lawson/cpchomec.htm) pour redistribution avec attribution et intégrité des avis de copyright, en avertissant qu'une permission distincte pouvait être nécessaire pour Locomotive Software. [Howard Fisher (1999)](https://groups.google.com/g/comp.sys.amstrad.8bit/c/HtpBU2Bzv_U/m/HhNDSU3MksAJ) décrit l'accord non-commercial de Locomotive pour l'intégration dans les émulateurs avec code ROM non modifié et demande de permission formelle pour la redistribution. **Aucune autorisation individuelle pour LOCO-CYD n'est revendiquée ici.**
- Le workflow clone le sous-module déjà public pour **exécuter temporairement** ses ROM non modifiées dans l'émulateur, sans les committer au dépôt parent, ni les inclure dans les artefacts. Les usages et droits hors du contexte strictement interne de test ne sont pas présumés ; si cette utilisation sur CI publique n'est pas juridiquement admissible, employer un runner privé muni d'une ROM autorisée. Le pilote accepte `--rom /chemin/autorise/cpc6128.rom` pour une ROM détenue légalement, et consigne son SHA.
- Ne pas uploader de `.rom`, de snapshot `.sna` contenant la ROM ou de dump complet 128 Kio non expurgé. L'artefact ne doit contenir que `cap32.cfg`, `autocmd.json`, `caprice.log`, `printer.dat`, screenshot PNG et `manifest.json`.

## Configuration et preuve d'acquisition

- Modèle **2 = CPC6128**, RAM **128 Kio**, 4 MHz, clavier CPC et PC anglais (0), interface SDL dans `xvfb-run`, audio désactivé, imprimante active ; une configuration régénérée par cas à partir du `cap32.cfg` amont est stockée dans chaque dossier d'artefact.
- ROM système combinée `rom/cpc6128.rom` de **32768 octets** à SHA-256 calculé au lancement ; ROM AMSDOS chargée en slot 7 si présente. Caprice32 annonce sa version (`--version`) et la CI vérifie le commit git. Le fait d'avoir le bon modèle et une ROM nommée `cpc6128.rom` ne constitue **pas à lui seul une authentification** de l'écran de démarrage BASIC 1.1 : examiner le screenshot et, à terme, vérifier l'identité de la ROM par comparaison à des empreintes de référence indépendantes.
- Deux scripts : `minimal` = `10 PRINT 5 / 20 END` ; `witness` = fichier historique préparé `c_integer_add.bas`. Après leur `RUN`, la commande **additionnelle** `PRINT #8,5` (minimal) ou `PRINT #8,B%` (witness) interroge la ROM via le port imprimante. Sa sortie est conservée **octet à octet** et un contrôle numérique indépendant (5) est exécuté ; ce contrôle n'est ni un flux `PRINT` écran ni une preuve de formatage CPC. Les images PNG sont preuve visuelle uniquement ; aucun OCR ni reconstruction de tokens.
- `manifest.json` (artefact de run, non promu à fixture) enregistre date UTC, commit, version, configuration, SHA ROM, SHA source, fichiers et leurs SHA-256/tailles, plus description de la méthode. Un fichier absent, vide ou malformé, un retour non nul, un timeout ou une valeur de sonde inattendue fait échouer la job. Les journaux des échecs sont néanmoins uploadés si disponibles.
- Pas de snapshot ni de dump token dans C1 : la capture ne sera acquise que lorsque son découpage mémoire, offsets et exclusion des ROM auront été vérifiés. Deux captures binaires de lignes restent nécessaires pour clôturer J0.24.

## Reproduction

Sur Ubuntu avec `pkg-config libsdl2-dev libfreetype6-dev zlib1g-dev libpng-dev xvfb xauth python3` :

```sh
git submodule update --init --recursive tests/oracles/caprice32
test "$(git -C tests/oracles/caprice32 rev-parse HEAD)" = "8c778bf072a06fb7c23b9cccd179041db7f79a52"
cd tests/oracles/caprice32
make -j2 WITHOUT_GL=1 APP_PATH="$PWD"
./cap32 --version
cd ../../..
python3 tests/oracles/run_caprice32.py --caprice tests/oracles/caprice32 \
  --output /tmp/lo-co-cpc-evidence --case minimal --case witness
```

Workflow CI indépendant : [`.github/workflows/cpc-oracle.yml`](../.github/workflows/cpc-oracle.yml), déclenché à la modification des fichiers oracle dans une PR ou manuellement via GitHub Actions. Il n'altère pas `tools/cpc_diff.py` ni `tests/fixtures/cpc6128/manifest.json` ; la **promotion** des preuves issues des artefacts nécessite la revue du manifeste, du rendu réel de la capture, et de la légalité des données redistribuées.
