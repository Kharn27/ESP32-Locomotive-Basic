# J0.24-C3 — Images BASIC tokenisées prélevées en RAM CPC 6128

**État initial de l'expérience : extraction préparée ; captures et classification à confirmer par GitHub Actions.** J0.24/J0→J1 restent ouverts ; J0.25 n'est pas lancé.

## Indépendance et source primaire

Référence fournie : `basic.asm`, désassemblage Locomotive BASIC 1.1 ; séquences Z80 `F53F–F558`, `E761–E76B` (création du programme vide), `E864–E86E` (parcours initial), `EBC…EC…` (édition de lignes). Ces routines fondent la localisation **sans lire les sorties de notre C99**.

- `(&AE64)` contient l'adresse de base `P` du stockage BASIC ; la ROM initialise l'octet `[P]` à `00`.
- Le premier mot de longueur se trouve à `P + 1` ; à programme vide, `[P+1:P+3] == 00 00`.
- `(&AE66)` pointe sur le premier octet libre `E`, après la sentinelle finale à deux octets.
- Les enregistrements à partir de `P+1` possèdent une longueur little-endian sur deux octets, puis un numéro de ligne little-endian sur deux octets, puis les tokens avec terminateur `00`. La sentinelle terminale vaut `00 00`. On impose l'égalité du point de fin parcouru et de `E`, pas une recherche de séquence C99.
- Le script vérifie `P`, `E`, ordre des numéros de ligne, tous les terminateurs et les numéros attendus depuis les sources ASCII non modifiées.

## Snapshot indépendant

Caprice32 v4.6.0, SHA figé `8c778bf072a06fb7c23b9cccd179041db7f79a52`, fichier `src/slotshandler.cpp` fonction `snapshot_save`, écrit en premier `sizeof(t_SNA_header)` suivi directement de `pbRAM` sur `CPC.ram_size * 1024` octets. Structure `t_SNA_header` déclarée dans `src/cap32.h` : en-tête SNA v3 de **256 octets**. La capture attend donc `256+131072` octets, signature `MV - SNA`, version 3, modèle 2, RAM 128 Ko et configuration Gate Array à banque physique zéro (offset header `0x41`). L'offset RAM physique du programme est **`0x100 + P + 1`**. `&AE64` et `&AE66` sont des adresses **RAM** du CPC (dans la zone `0x8000…0xBFFF`), et non des octets extraits de la ROM de BASIC.

L'acquisition utilise `--autocmd` : saisie des lignes exactes, `LIST`, deux délais, capture écran de LIST, `CAP32_SNAPSHOT`, puis `CAP32_EXIT`, **sans RUN**. Le snapshot complet n'existe que dans un `TemporaryDirectory` du runner ; `program.bin`, `c99.bin`, manifestes, trace de commandes et éventuellement capture PNG de LIST sont les seuls fichiers exportés. **Jamais de snapshot .sna, de ROM ni de dump RAM complet dans un artefact ou Git.** L'image native C99 est produite séparément par `basic_program_image_cli`.

## Comparaison

Le classement est `MATCH_EXACT` en cas d'égalité octet par octet, `DIFF` autrement ; aucune normalisation ni équivalence sémantique non prouvée. En cas de divergence : premier offset, octet CPC, octet C99 et fenêtres hexadécimales. La divergence reste un résultat scientifique recevable : seule une acquisition corrompue fait échouer l'étape oracle. La preuve de LIST repose sur l'émission de la commande, la capture PNG et la vérification séparée des lignes tokenisées en RAM ; la transcription visuelle de la capture doit être revue avant promotion de la fixture en Git.

Le workflow reste `permissions: contents: read`. Promotion durable uniquement dans une PR après vérification des empreintes, des captures et des limites de publication. Les 22 CTest C99 ordinaires ne nécessitent ni ROM ni Caprice32.

## Reproduction

```bash
git submodule update --init --recursive tests/oracles/caprice32
cd tests/oracles/caprice32
make -j2 WITHOUT_GL=1 APP_PATH="$PWD"
cd ../../..
cmake -S . -B build && cmake --build build -j2
ctest --test-dir build --output-on-failure
python3 tests/oracles/token_ram_oracle.py --self-test
python3 tests/oracles/token_ram_oracle.py \
  --caprice tests/oracles/caprice32 --image-cli build/basic_program_image_cli \
  --output /tmp/loco-cpc-c3
```

**Vigilance :** la classification ne sera rapportée comme historique qu'après inspection effective des images binaires issues de Caprice32. L'acquisition est exécutée sur GitHub Actions ; elle n'a pas été simulée à partir du C99.

### Limitation avérée du `--autocmd` Caprice32 épinglé

Dans `src/argparse.cpp`, `replaceCap32Keys()` reconnaît `CAP32_SCRNSHOT`, `CAP32_DELAY` et `CAP32_EXIT`, **mais omet `CAP32_SNAPSHOT`** alors que la commande existe dans `src/keyboard.h`, `src/keyboard.cpp` et le dispatch de `src/cap32.cpp`. Le premier essai CI a échoué : aucun fichier `.sna` trouvé. Le correctif d'automatisation n'altère pas l'émulateur : il transmet la séquence d'événement native `form-feed (0x0c), 0x0d` correspondant à `MOD_EMU_KEY + 13` pour déclencher `CAP32_SNAPSHOT`. L'intention textuelle est conservée dans `autocmd.json`. À confirmer par un nouvel essai réel.
