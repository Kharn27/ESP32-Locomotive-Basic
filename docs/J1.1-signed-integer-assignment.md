**Statut : livrée pour revue contradictoire Pilotage, PR #54 ouverte, non fusionnée.**
Base du travail : `main` `5c27408382c9f97a6d16f33a67328a22f8affdd4`
(J0 définitivement accepté/clôturé par Pilotage après PR #53).

## Objectif et portée

Faire exécuter, par saisie BASIC, tokenisation, LIST et RUN pas à pas :

```basic
10 B%=-1
20 PRINT B%
30 END
```

et le programme analogue avec `B%=-12`.

L'implémentation ne crée **pas** de moteur d'expression général. Un signe unaire est accepté **uniquement devant une valeur entière littérale** pour une affectation INTEGER scalaire autonome. Il demeure interdit après `source%+`, devant une variable et comme opérateur binaire. L'amplitude des littéraux reste bornée à 0..255 par le chemin existant. `32767` et `-32768` sont exclus de la saisie BASIC dans J1.1.

## Implémentation native

- Tokenizer : émet `F5` puis `0F` ou `19 0C`; conserve l'encodage CPC des références `02 00 00 C2`. Les autres expressions restent rejetées.
- Listing : rend `-1` et `-12` à partir du couple token-signe / constante ; vérifie les séquences tronquées et invalides.
- Exécuteur : détecte `F5` devant la constante existante, calcule la négation après lecture bornée, puis remet le résultat `int16_t` au même mécanisme d'affectation à **deux passes** qui était déjà atomique. Aucun `malloc`, pas de buffers ni de magasin globaux, pas d'évolution de l'ABI.
- PRINT : code J0.27-C1 inchangé ; rendu signé avec espace final et LF sous Linux.

```
C99 -1  : 2D 31 20 0A
C99 -12 : 2D 31 32 20 0A
CPC B2 -1  : 2D 31 20 0D 0A
CPC B2 -12 : 2D 31 32 20 0D 0A
```

Les corps de présentation sont comparables par `MATCH_PRESENTATION`, **jamais les transports entiers comme `MATCH_EXACT`**. Les screenshots CPC sont `VISUAL_OBSERVATION` ; aucun caractère écran byte-exact n'est attesté.
