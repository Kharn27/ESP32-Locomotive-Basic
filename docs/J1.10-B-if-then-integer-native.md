# J1.10-B — IF…THEN INTEGER natif (C99)

Mandat : issue #106. Base main : c9ff43bd4a04d88fe3552a9398cefc0804651b83 (J1.10-A fusionné). Branche : feat/j1-10-b-native-if-then-integer. Acceptation et fusion réservées au PILOTAGE.

## Frontière du code

Instruction autonome de ligne numérotée : IF variable% THEN numéro. Variable INTEGER explicite et cible littérale décimale entre 1 et 65535 ; aucun autre opérande ni suffixe. Tokenisation CPC A1, référence 02 cache-low cache-high nom-bit7, EB THEN, 1E cible-LE16. Les espaces sont conservés ; cache BVR historique initialement nul. LIST restitue une source tokenisable et lit les deux caches comme des octets opaques (même 20 ou EF).

Exécution : lire sans mutation la variable liée avec bvb_read_explicit ; si zéro, avancer vers la ligne suivante sans rechercher la cible. Si non zéro, bp_find puis une seule transition du curseur. Si la cible prise n'existe pas, BE_MISSING_TARGET sans mutation de la sortie, de written, du curseur, du stockage BASIC ou des variables. IF ne produit aucun octet. Le protocole END/BE_END existant est conservé. Aucune nouvelle couche ERR/ERL.

## Oracle CPC indépendant et différentiel

Origine J1.10-A : manifeste SHA-256 4439054c55c9422aba315c3e5e4cc4303c38b34c4b1f2f13ba56e60f69661796 ; 14 originaux RAM et imprimante scellés, classifications historiques 14/14 UNSUPPORTED avant implémentation maintenues telles quelles. Le script tools/j1_10_b_native_verify.py lance d'abord tools/j1_10_if_then_verify.py --permanent --self-test, et vérifie les informations du manifeste.

L'adaptation native est strictement limitée aux lignes PRINT #8,entier -> PRINT entier (ne jamais modifier les sources originelles ni affirmer prendre en charge PRINT #8). Chaque enregistrement IF de l'image C99 adaptée est comparé intégralement au record CPC indépendant, y compris longueur, numéro, A1, cache, EB, 1E, cible et fin ; le cas de saut arrière contient deux IF. Le programme.bin entier n'est PAS annoncé identique car les PRINT adaptés changent les octets. LIST doit reproduire la source adaptée. La sortie console Linux est analysée en lignes numériques, confrontées aux 14 traces immuables de l'imprimante CPC (sans affirmer une identité octet-à-octet de transport/formatage). Deux falsifications isolées visent le record IF et la trace attendue.

Sur F_TRUE_MISSING, le CPC observe ERR=8 et ERL=20 ; côté hôte, l'équivalent sémantique est BE_MISSING_TARGET. Ce n'est pas un code ERR numérique de l'API hôte ni une preuve d'atomicité de la ROM.

## J1.10-B-C1 — correctif du round-trip LIST sur IF importés

**Mandat correctif :** revue contradictoire Pilotage PR #107, revue 5676377810 ; fusion différée. Le défaut concerne exclusivement les enregistrements tokenisés IF valides auxquels manquent un ou plusieurs espaces source, et non les 14 lignes CPC canoniques scellées (toutes espacées).

Cas minimaux de l'ancienne implémentation (les suites représentent des **corps** de ligne, hors en-tête CPC et terminator final) :

- `A1 02 00 00 C1 20 EB 20 1E 3C 00` : ancien LIST `IFA% THEN 60` ;
- `A1 20 02 00 00 C1 EB 20 1E 3C 00` : ancien LIST `IF A%THEN 60` ;
- `A1 20 02 00 00 C1 20 EB 1E 3C 00` : ancien LIST `IF A% THEN60`.

Ces trois textes sont rejetés à la nouvelle tokenisation bien que l'enregistrement initial puisse être exécuté. La correction se limite à `core/basic_listing.c` : **un espace ajouté si et seulement si aucun espace n'est présent** aux frontières IF/référence INTEGER, référence INTEGER/THEN et THEN/cible. Le décodeur conserve les espaces déjà présents, même multiples ; les deux octets BVR `20 EF`, lorsqu'ils sont des caches, ne sont jamais interprétés comme des espaces lexicaux. Aucun changement de grammaire du tokenizer ou de la sémantique RUN.

La nouvelle régression C99 parcourt les **8 masques** de présence/absence des trois frontières et **2 caches** (00 00 et 20 EF), vérifie un import d'image CPC-shaped via `bp_import`, LIST exact et non mutant, `BL_NO_SPACE` (capacité nulle et insuffisante), succès à la capacité exacte, absence de mutation de sortie et `written` en cas d'échec, re-tokenisation `BT_OK`, préservation sémantique des cibles, branchement zéro/non-zéro `BE_OK`, et conservation des octets originaux dans l'image importée. Pour les imports non canoniques, une re-tokenisation **peut créer des espaces** : on exige l'équivalence sémantique, pas leur égalité byte-à-byte à la représentation importée.

Les **14 enregistrements IF canoniques de J1.10-A restent contrôlés MATCH_EXACT** par le différentiel historique, sans modifier les captures ou leur manifeste. Le comparateur post-B conserve la transformation très bornée `PRINT #8,n` en `PRINT n` pour les seules traces numériques.
