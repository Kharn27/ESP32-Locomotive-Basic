# J1.14-A — Oracle CPC6128 IF instruction directe / ELSE

Mandat exclusif : [issue #134](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/134). Base : `main@ec56bad2b6cd9d920d6a590ac63c3c6f94a02ffb`. **Aucune implémentation native** ; J1.14-B n'est pas autorisé.

## Protocole

Le collecteur `tests/oracles/j1_14_if_inline_else_oracle.py` utilise Caprice32 `8c778bf072a06fb7c23b9cccd179041db7f79a52`, ROM CPC 6128 SHA256 `31c3668c67bea027dab698ece233c9434d9324f9ba7dac84db58f400b6689562`, image GHCR épinglée `sha256:7c2ac82df92a2df5c7305cc0bd70dc95124249fb46b2d893449f3d48395ced8c`.

Chaque cas positif a **deux couples** de processus indépendants : LIST et snapshot pré-RUN, puis RUN et imprimante `PRINT #8,C%` ; après RUN des sondes directes `PRINT #8,ERR` et `PRINT #8,ERL` sont exécutées. Extraction des enregistrements BASIC originaux depuis les pointeurs ROM `&AE64` et `&AE66` dans un SNA CPC6128 128 Kio temporaire supprimé avant archivage. Conservation du record **ligne 30 complet** incluant longueur, numéro, caches CPC, espaces, tokens et terminateur. Le canal écran PNG est un témoin visuel non textuel. Pas d'égalité entre imprimante CPC et stdout C99.

`token_ram_oracle.acquire` effectue aussi un export C99 **pré-implémentation** pour enregistrer `UNSUPPORTED` ou la classification effectivement constatée, sans jamais déclarer l'exécution native du nouveau IF. Le vérificateur `tools/j1_14_if_inline_else_verify.py` utilise les inventaires SHA par fichier et un ancrage externe du manifeste, de la RAM, de l'imprimante et des résultats observés ; ces ancrages ne sont remplis **qu'après** une première acquisition GitHub réelle. Avant ancrage, `--permanent --self-test` échoue volontairement.

## Hypothèses ROM et exclusions

Les entrées `IF=C767` (`A1`), `THEN=EB`, `ELSE=97`, traitement `ELSE=E9AD` sont des **indices issus de `basic.asm`**, non des bytes d'oracle. Le collecteur archive les octets observés indépendamment ; les caches variables restent opaques, et l'existence de séparateurs après ELSE est à documenter uniquement depuis l'image CPC. La syntaxe `THEN GOTO`, le chaînage, ELSE imbriqué, le code écran/HW4 et toutes les extensions de J1.14-B sont exclus.

## Résultats et barrières

En attente de première acquisition indépendante et d'ancrage externe : **ne pas attribuer** de `CPC_ORACLE_VERIFIED` avant 24/24 doubles RAM + 24/24 doubles imprimantes et tests de permanence/falsification. Quatre cellules GCC/Clang × sanitizers OFF/ON, CI-CPC-PERMANENT, CI-ARCH et Xtensa 3/3 obligatoires sur HEAD final ; budgets Flash/IRAM/DRAM à relever sur les trois images. Aucune validation physique requise : `ON_DEVICE_UNVERIFIED`. Revue/acceptation/fusion réservées au Pilotage.
