Mandat : [issue #144](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/144). Base obligatoire : `main@7a471da5088981d64724f43183c87db20a2b16ae`. Oracle seul : J1.15-B non autorisé, aucune modification `core/` ni `firmware/`.

## Provenance, séparation des canaux
L'acquisition `tests/oracles/j1_15_string_scalar_oracle.py` réutilise l'extracteur d'origine `token_ram_oracle.acquire`. Caprice32 `8c778bf072a06fb7c23b9cccd179041db7f79a52` ; ROM CPC6128 SHA-256 `31c3668c67bea027dab698ece233c9434d9324f9ba7dac84db58f400b6689562` ; image GHCR SHA-256 `7c2ac82df92a2df5c7305cc0bd70dc95124249fb46b2d893449f3d48395ced8c`.

Pour chaque candidat : deux processus CPC LIST/SNA pré-RUN indépendants avec extraction de RAM aux pointeurs `&AE64`/`&AE66` et conservation des enregistrements complets + `00 00` ; deux processus RUN/imprimante indépendants. Les SNA et ROM complètes restent temporaires, non publiées. `list.png` et `run.png` sont des preuves visuelles non textuelles. La sortie imprimante conserve exactement les espaces, CR/LF, octets et ordres de lignes ; elle n'est pas assimilée à l'écran ni à stdout C99.

**Instrumentation explicite :** les sources contiennent `PRINT A$` pour l'écran et `PRINT #8,A$` pour obtenir le canal imprimante. Ainsi, le record du programme instrumenté est plus long que celui de l'exemple minimal `10 A$="BONJOUR"/20 PRINT A$/30 END` : `PRINT #8` est une ligne additionnelle et fait partie des octets archivés. Les commandes directes `PRINT #8,ERR` puis `PRINT #8,ERL`, exécutées **après RUN**, ajoutent deux lignes à l'imprimante mais aucun octet au programme pré-RUN. Pour deux variables, deux lignes imprimante sont capturées. Les deux dernières lignes de l'imprimante sont analysées comme nombres ; toutes les autres lignes restent des octets binaires, sans normalisation.

## Source ROM : hypothèses séparées des observations
`basic.asm` : affectation `&D68E` et `&D69F` ; résolution de variable `&D6BF` ; évaluation tokenisée `&D033` ; chaîne quotée `&F879` ; PRINT `&F2A4` et `&F2D2` ; sortie imprimante `&C438`. Ce sont **des repères de désassemblage**, pas des preuves de la représentation des octets `A$`. Les marqueurs, les caches opaques, les noms et les quotes seront analysés exclusivement à partir de la RAM capturée.
