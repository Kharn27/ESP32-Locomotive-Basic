# J1.15-B — Variables STRING scalaires natives C99

**Mandat Pilotage :** [issue #147](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/147). **Base obligatoire :** `main@e019a0cdd67730df21b8737d62e32fb6f1ffe2ea`. **PR :** [#148](https://github.com/Kharn27/ESP32-Locomotive-Basic/pull/148). **Frontière :** C99 portable seulement ; aucune modification du firmware, de l'écran, des archives CPC ni intégration de l'arène dans la CYD.

## Contrat mémoire et atomicité

`BasicVariableStore` conserve `bvs_init(store,entries,capacity)` pour les clients historiques (sans arène). Nouvelle API `bvs_init_with_arena(store,entries,capacity,arena,arena_capacity)`, suivie de `bvs_can_assign_string` et `bvs_assign_string` ; `bvs_string_span` rend une vue empruntée, non NUL-terminée. Aucun `malloc`, `realloc`, état global, récupération implicite d'une allocation ou PSRAM. L'arène et les entrées sont **des objets distincts fournis par l'appelant** et empruntés durant toute la durée de vie du magasin.

Pour garantir la réaffectation illimitée sans copie temporaire, l'arène est **découpée par index d'entrée** : `slot_bytes = floor(arena_capacity / entry_capacity)`. Chaque entrée, y compris INTEGER, réserve potentiellement son slot ; une chaîne de longueur `n` requiert `n <= slot_bytes` ; son `BasicStringValue {offset,length}` vaut `{index*slot_bytes,n}`, avec `{0,0}` pour une chaîne vide. La partie restante de l'arène est inutilisée ; il s'agit volontairement d'une politique **hôte conservatrice** et non d'une limite historique CPC. Compromis explicite : pas de fragmentation, de compaction, de fuite ni de consommation cumulative lors des réaffectations, mais capacité moins dense qu'un allocateur variable.

Toutes les vérifications (nom canonique, type, cache CPC du chemin natif, NUL/CR/LF/guillemets, longueur, capacité, nombre d'entrées, alias avec toute l'arène/les entrées/programme/sortie) se font **avant** écriture du slot. Une réaffectation réussie efface l'ancienne tranche et copie les nouveaux octets ; `RUN` et `NEW` réinitialisent le magasin et effacent l'arène. Les opérations en erreur conservent compteur/entrées/arène, programme, sortie et curseur. Les statuts `BVS_NO_STRING_SPACE`, `BVS_INVALID_STRING`, `BE_STORE_FULL`, `BE_NO_SPACE` et `BE_VARIABLE_NOT_FOUND` restent **internes C99**, jamais identifiés à des codes CPC `ERR`.

La taille supplémentaire de `BasicVariableStore` correspond à un pointeur et deux `size_t` (12 octets sur ESP32 32 bits, 24 sur Linux 64 bits). Dans le profil `BASIC_PROBE`, le rapport ABI ELF lié attend désormais `BasicVariableStore=24 bytes`, `LocoProbeStorage=19084 bytes` et `core_descriptor_bytes=648` (anciennement 12 / 19072 / 636). La barrière correspondante est modifiée uniquement dans `.github/workflows/ci-xtensa.yml` afin d'interdire un retour silencieux à l'ABI ancien ; aucun code firmware n'est modifié. **L'arène elle-même n'est pas statiquement ajoutée au firmware** dans ce jalon ; les trois binaires Xtensa doivent être mesurés sur le HEAD final, pas extrapolés à partir de cette description.

## Grammaire native fermée

- Affectation autonome `A$="texte"` ou `LET A$="texte"` : nom explicite terminé par `$`, littéral ASCII imprimable court, quotes appariées, éventuellement vide, espaces source conservés ; aucun terme RHS ou statement supplémentaire.
- Lecture `PRINT A$` : stockage déjà créé explicitement, valeur pure (aucune création implicite), émission de la chaîne suivie du **LF hôte**. `PRINT "littéral"` et les chemins INTEGER/FOR/IF/GOSUB déjà existants sont préservés.
- Record CPC : marqueur STRING `03`, deux caches `00 00` pour les **assignations natives** (ni pointeurs, ni adresses réelles), nom à dernier octet haut, `EF` pour `=`, quotes `22`. Le code C99 suit les bytes observés sur `basic.asm`/RAM J1.15-A, sans synthèse d'images CPC entières.
- Le `PRINT` historique acceptait déjà les caches arbitraires sur le chemin LIST ; ce contrat est préservé pour les imports existants. La nouvelle exécution lit le cache 00 00 pour `PRINT A$` des cas pris en charge.

Sont exclus de l'acceptation : `S_TWO_VARS` comme preuve de `PRINT A$:PRINT B$` et `S_UNINITIALIZED` (aucune valeur implicite), `PRINT #8`, fonctions chaînes, quotes doublées/non closes, concaténation, conversion et tableaux, autre type non INTEGER/STRING, autres extensions d'expressions, firmware et SDL.

## Protocole différentiel ROM — sous-ensemble exact

**Source oracle figée :** [J1.15-A](J1.15-A-string-scalar-cpc-oracle.md), archive `tests/fixtures/cpc6128/j1_15_string_scalar/`, origine manifeste SHA-256 `c37b24176d276edca6249cfe60891e6a5533e68eb3be67ba9b2a80118076d49f`. Les originaux portent le sceau `PENDING_PILOTAGE` et les verdicts **pré-B 14/14 UNSUPPORTED** ; ils ne sont pas réécrits.

`tests/test_j1_15_b_string_native.c` lit les sources réelles des **12 cas autonomes**, ne soumet pas à la session C99 la ligne instrumentée `PRINT #8`, puis compare **octet par octet chaque record de ligne restante** (longueur, numéro, token, caches, chaîne, terminateur) avec son record d'origine `program.bin`. La ligne `PRINT #8` demeure conservée dans les originaux, pas prétendue exécutée. La sortie `LIST` est retokenisée et sa nouvelle image égale au programme natif. L'outil lit aussi **la première ligne brute du fichier historique `run/printer.dat`** dans les archives originales : il vérifie exactement valeur ASCII + `0D 0A`, puis compare la valeur native + `0A` sans conclure à une égalité de transports. `RUN` compare la valeur imprimée côté C99 : **`MATCH_SEMANTIC_VALUE`**, et non `MATCH_EXACT` entre stdout/écran et canal imprimante CPC.

| Cas | Variation | Valeur attendue hors transport |
|---|---|---|
| `S_EMPTY` | chaîne vide | `\n` |
| `S_ONE` | 1 caractère | `X\n` |
| `S_HELLO` | BONJOUR | `BONJOUR\n` |
| `S_DIGITS` | chiffres | `12345\n` |
| `S_LEADING` | espaces initiaux | `  DEBUT\n` |
| `S_TRAILING` | espaces finaux | `FIN  \n` |
| `S_COLON` | deux-points | `A:B:C\n` |
| `S_REASSIGN` | réaffectation | `APRES\n` |
| `S_LOWERCASE` | nom minuscule | `minuscules\n` |
| `S_LET_SPACES` | LET/espaces | `ESPACES\n` |
| `S_LONG_NAME` | nom long | `NOM LONG\n` |
| `S_INNER_SPACE` | espaces internes | `UN DEUX TROIS\n` |

`S_TWO_VARS` conserve le PNG LIST non identique entre acquisitions J1.15-A ; `E_DOUBLE_QUOTE`/`E_UNCLOSED_QUOTE` restent exploratoires. Aucune preuve d'exécution de `PRINT #8` ou d'égalité totale du programme instrumenté n'est revendiquée.

## Négatifs et contrôles

Le test C99 couvre absence d'arène, chaîne vide sans arène, quota strict par slot, dépassement d'un octet, écrasement/réaffectation répétée (100 fois), épuisement d'entrées, aliasage entrée/arène, chaînes contenant guillemets/NUL, quotes invalides, expression RHS interdite, sortie trop petite sans mutation d'état, et reset `RUN`/`NEW`. Il vérifie canaris/bytes inchangés dans les cas négatifs et compare les références partielles à la RAM originale. Les autres 85 CTests historiques restent obligatoires, avec GCC/Clang OFF/ON ASan/UBSan, CPC indépendant/permanent, CI-ARCH/HW4 et Xtensa ESP-IDF v5.5.6.
