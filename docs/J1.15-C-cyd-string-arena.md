# J1.15-C — Arène STRING du firmware CYD (CONSOLE)

**Mandat :** [issue #152](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/152). **Base obligatoire :** `main@ed7c82a4cb0ae08c853710ece6bffb098887999f` (fusion J1.15-B / PR #148). **Branche :** `feat/j1-15-c-cyd-string-arena`. **Acceptation / fusion : Pilotage uniquement, après tests physiques PO.**

## Implémentation minimale

- **Firmware CONSOLE seulement :** `BasicStorage` possède `string_arena[4096]` statique au sein du même objet `s_basic`, distinct de `entries[64]`, `bytes[8192]`, `temporary[2048]`, `output[4096]` et VRAM. Aucun `malloc`, aucune PSRAM, aucune seconde instance ni variable globale supplémentaire. `j115c_init_store` appelle le `bvs_init_with_arena` du moteur accepté, sans modification de `core/`.
- **Source de vérité partagée :** `firmware/esp32_display_probe/main/j1_15_c_string_arena.h` fixe `64 × 64 = 4096` via des constantes utilisées aussi dans le CTest; l'enveloppe est un **quota hôte par variable**, pas une borne historique du CPC. Contrôles C99 à la compilation et à l'initialisation sur les 64 entrées, les 4096 octets, les 64 octets/slot, le pointeur d'arène, la validation du magasin. Une taille incorrecte donne une erreur explicite avant utilisation. Le firmware affiche `J1.15-C BASIC_ARENA_READY ...` seulement après initialisation correcte.
- **Réinitialisation :** `RUN` et `NEW` passent par les resets de J1.15-B, effaçant l'arène ; remplacer une chaîne par plus courte, vide ou longue conserve le même slot déterministe. Une longueur 65 excède le quota et retourne `BVS_NO_STRING_SPACE` / `BE_STORE_FULL` **interne** sans troncation.
- **Périmètre inchangé :** MODE 1 320×200 et 40×25, UART, `LIST`, `PRINT_BYTES`, `BSR_END`, scrolling, éditeur Backspace/Left/Right/Delete, unique LCD/DMA, fonctions INTEGER ; aucun nouveau BASIC STRING, `PRINT #8`, fonctions de chaînes, éditeur, palette, rendu ou oracle modifié.

## Preuves automatisées et falsifications

Le test `j1_15_c_cyd_console_string_arena` construit un runtime C99 avec **le même initialiseur et les mêmes constantes que CONSOLE**. Cas couverts : 4096 octets / 64 slots × 64, refus atomique 4095 octets ou 63 entrées, `BONJOUR\n` et un seul événement PRINT, deuxième `RUN`, `SALUT`, chaîne vide `0A`, nouvelle affectation, `NEW` puis `LIST` vide, 64 caractères admis, 65 refusés à `RUN` sans sortie ni mutation du magasin/arène et sous la capacité UART 120, `A%=1` / `PRINT A%` et `BSR_END`.

`tools/ci/check_u1b_memory.py` ne retire **aucune** borne existante : IRAM CONSOLE garde `+2048` ; une unique enveloppe supplémentaire de **4096 octets DRAM** est autorisée **seulement CONSOLE**, **seulement après** vérification conjointe du contrat exact 64×64, du raccordement de l'arène dans la source du firmware et du symbole `s_basic` de l'ELF via `nm -S`. Maximum CONSOLE DRAM : baseline U1-B `49368 + 2048 + 4096 = 55512` octets ; le chiffre observé doit être inférieur. HW3/BASIC_PROBE : garde RAM indépendante `+2048` au maximum et refus d'un `s_basic` lié. Les falsifications incluent +1 au-dessus du seuil (`+6145` CONSOLE), +2049 sans attestation, fausse taille de slot, faux symbole, symbole sous-dimensionné/dupliqué et nouvelles arènes dans HW3/BASIC_PROBE. Aucune modification des tests ni des empreintes CPC J1.15-A.

**État des preuves :** CI GitHub du HEAD final à renseigner après résultats. Le CTest de base est **86 tests par cellule** sur `main`; J1.15-C ajoute 1 CTest, soit **87 par cellule attendus**, à confirmer, pas à présumer.

## Protocole obligatoire PO — CYD ESP32-2432S028R sans PSRAM

**Précondition :** relever ci-dessous l'URL de PR et le **SHA complet du HEAD final figé** ; ne pas flasher un autre commit. La CI et la compilation ESP-IDF ne remplacent pas le test de cette carte.

1. Dans Debian/VS Code (ESP-IDF **5.5.6**), checkout de la branche dédiée au SHA complet de la remise. Ouvrir **`firmware/esp32_display_probe`**, pas une ancienne racine. Contrôler `git rev-parse HEAD` et `git status --short` ; sélectionner `/dev/ttyUSB0` (ou le port réel). Commandes usuelles :

   ```sh
   git switch feat/j1-15-c-cyd-string-arena
   git pull --ff-only
   git rev-parse HEAD
   cd firmware/esp32_display_probe
   idf.py fullclean build flash monitor -p /dev/ttyUSB0
   ```

   Si `idf.py` requiert un ordre séparé : `idf.py fullclean`, `idf.py build`, `idf.py -p /dev/ttyUSB0 flash monitor`. Confirmer dans le journal de boot `App version` = **7 premiers caractères du SHA complet**.

2. Démarrage : `LCD_INIT_PASS`, `VIDEO_READY mode=1`, `UART_READY`, `J1.15-C BASIC_ARENA_READY entries=64 slot_bytes=64 arena_bytes=4096 allocation=static`, puis `Ready`. Conserver `DEVICE_MEMORY stage=before_lcd`, `interactive_ready` et `after_line`. Zéro `dma_fault`, `dma_timeouts`, `LCD_FAIL_STOP`, `panic` ; `lcd_error=ESP_OK`. Photographier l'écran et le curseur.

3. Coller **une commande par ligne** sur UART, saisir `NEW`, `10 A$="BONJOUR"`, `20 PRINT A$`, `30 END`, puis `LIST` et `RUN`. Vérifier le `LIST` et **BONJOUR visible sur LCD** ; sortie UART attendue : **un seul** `PRINT_BYTES length=8 hex=424f4e4a4f55520a`, suivi de `BSR_END status=BE_END`, sans `BSR_STEP_FAIL`.

4. Refaire `RUN` (même résultat), remplacer par `10 A$="SALUT"`, `RUN` ⇒ **SALUT** (`53414c55540a`), puis `NEW` et `LIST` ⇒ programme vide. Saisir `10 A$=""`, `20 PRINT A$`, `30 END`, `RUN` ⇒ une seule sortie `PRINT_BYTES length=1 hex=0a`. Chaque commande doit revenir à `Ready`.

5. INTEGER : `NEW`, `10 A%=1`, `20 PRINT A%`, `30 END`, `RUN` ⇒ sortie numérique de 1 au format natif déjà accepté, `BSR_END`. Vérifier édition (Backspace et Delete) et scrolling sans altération ni défaut DMA.

6. **Négatif 65 caractères** (facultatif sur carte si peu pratique, **obligatoire en CI**) : préparer la ligne sans la taper manuellement en l'affichant puis en la collant via le terminal UART :
   ```sh
   python3 -c 'print("10 A$=\"" + "X"*65 + "\"")'
   ```
   Sur carte : `NEW`, la ligne générée, `20 PRINT A$`, `30 END`, `RUN`. La ligne fait 73 octets (inférieure aux 120 acceptés par l'éditeur). Attendu `BSR_STEP_FAIL` avec `BE_STORE_FULL` (diagnostic interne normal pour cette **seule** entrée), **aucun PRINT**, aucun crash/DMA fault, puis retour `Ready`. Ne pas confondre cet échec attendu avec l'échec interdit du scénario BONJOUR.

7. **À transmettre au Pilotage :** SHA complet réellement flashé, boot avec `App version`, capture(s) LCD, journal UART brut des scénarios, `PRINT_BYTES`/ `BSR_END`, relevés `DEVICE_MEMORY` de plusieurs étapes (heap libre, plus grand bloc, minimum, marge de pile), compteur DMA et erreur LCD ; tableau PASS/FAIL par scénario. Ne pas recycler une capture ancienne. Si échec, conserver le log et expliquer à quelle étape, sans attribuer sans diagnostic.
