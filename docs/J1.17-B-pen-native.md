Les valeurs **5..14** sont seulement tokenisées/listées : leur exécution répond **BE_UNSUPPORTED**, état `UNVERIFIED` ; on ne prétend pas qu'elles sont invalides CPC. L'argument `PEN` reste une constante immédiate, jamais une variable/expression, ni `PEN #`, ni transparence. **PEN 4 et PEN 15 sont acceptés sans consultation des limites de couleurs du MODE courant**. Ces événements n'entraînent **aucun pixel et aucun octet PRINT**.

## API portable / atomicité

Les API historiques `be_step` et `bsr_step` restent exportées, sans changement de signature ni d'agencement des structures existantes. Nouveaux appels facultatifs :

```c
BEStatus be_step_events(BasicExecutor *, uint8_t *print_bytes,
                        size_t print_capacity, size_t *printed,
                        BEVideoEvent *events, size_t event_capacity,
                        size_t *events_written);
BSRResult bsr_step_events(BasicSessionRuntime *, uint8_t *print_bytes,
                          size_t print_capacity, size_t *printed,
                          BEVideoEvent *events, size_t event_capacity,
                          size_t *events_written);
```

Chaque `BEVideoEvent` contient `type=BE_VIDEO_SET_TEXT_PEN`, `pen` et `print_offset`. Ce dernier est le nombre d'octets PRINT **précédant** l'événement dans la ligne exécutée. Une ligne `PEN 4:PRINT "X":PEN 15:PRINT "Y"` retourne deux événements (offsets 0,2) et les quatre octets de sortie `58 0A 59 0A` : l'appelant peut entrelacer la sortie et les événements sans détourner stdout. `10 PEN 4 / 20 PRINT "X" / 30 END` émet d'abord un événement sans stdout, puis les deux octets historiques `58 0A` à l'étape suivante.

Les deux canaux sont caller-owned, bornés et disjoints. Un compteur d'événements est requis même sans récepteur ; `events=NULL, capacity=0` est autorisé mais un `PEN` atteint retourne `BE_EVENT_RECEIVER_REQUIRED` sans avancer. Un tableau trop court retourne `BE_NO_EVENT_SPACE`. La passe de validation complète précède la passe d'écriture et le commit ; sorties, compteurs, programme, curseur et store restent inchangés sur erreur. Les contre-exemples ciblent token tronqué, entier invalide, arguments non mesurés, absence de récepteur, overlap et capacité partielle. `BE_INVALID_PEN` n'est **pas** un mapping de ERR CPC 5.
