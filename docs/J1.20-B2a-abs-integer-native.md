# J1.20-B2a — ABS INTEGER natif borné (moteur C99)

**Mandat Pilotage :** [#260](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/260) ; PR native [#261](https://github.com/Kharn27/ESP32-Locomotive-Basic/pull/261), DRAFT, réservée à la revue et fusion par Pilotage.
**Base figée à l'ouverture :** `main@748c49ee9376c48014aff0efe6a2e909e68bb01a`. Le SHA HEAD définitif et les CI sont consignés dans la PR après tests.

## Frontière réelle de l'incrément

- CPC `FF 00` suivi de `(`, d'un seul immédiat INTEGER canonique `0E..17`, `19 nn`, `1A lo hi` ou référence explicite INTEGER `02` (résolue en lecture seule), et de `)`. Signe unaire CPC `F5` admis pour les immédiats. Aucune modification de la tokenisation ou de LIST : B1 n'accepte lexicalement que ses cas déjà scellés (PRINT littéral 0, 1, -1, -32768 ou A%, et B%=ABS(A%)).
- L'évaluation se fait en `int32_t` ; la conversion vers `int16_t` n'intervient qu'après contrôle de la borne. `-32768` et tout résultat hors INTEGER16 borné sont **BE_UNSUPPORTED / TYPE_UNVERIFIED** ; pas de wrap, pas d'overflow signé C99, pas d'erreur CPC inventée. L'opérateur ABS n'est pas un nouveau moteur REAL5.
- `PRINT ABS(x)` réutilise `emit_integer` (espace de signe, chiffres, espace final) puis le LF de la ligne ; `B%=ABS(A%)` réutilise la prévalidation capacité et l'assignation atomique existante. `be_preview_step_events` et `be_step_events` partagent l'évaluation en lecture seule, sans allocation. En échec : sortie, curseur, store, programme et compteurs restent inchangés.
- Aucun `PRINT #8` natif ajouté. Le flux CPC original est imprimante `CRLF` ; la sortie C99 supportée est `LF`. Confronter la **valeur/format de l'entier**, pas prétendre à une identité d'octets ou une exécution complète des programmes CPC.
- La référence n'est jamais recherchée dans une chaîne, un REM ou le payload opaque d'une autre instruction : uniquement après le token PRINT ou le `=` d'une affectation INTEGER, avec exactement le `FF 00` courant.

## Matrice explicite : 16 témoins scellés J1.20-A

Sources : [dossier permanent J1.20-A](https://github.com/Kharn27/ESP32-Locomotive-Basic/blob/main/docs/J1.20-A-abs-integer-cpc-oracle.md) et [PR oracle #204](https://github.com/Kharn27/ESP32-Locomotive-Basic/pull/204). Les deux acquisitions originales et repeat, captures RAM, imprimante et écran, restent **immutables**. Les statuts ci-dessous concernent le **sous-chemin natif**, pas l'exécution end-to-end de l'imprimante.

| Cas | CPC constaté, valeur/erreur | Sous-chemin natif B2a | Classement / limite |
|---|---|---|---|
| A00 | ABS(0) = 0 | PRINT ` 0 \n` | **PARTIAL** : valeur/format hors CRLF conformes ; #8 non supporté |
| A01 | ABS(1) = 1 | PRINT ` 1 \n` | **PARTIAL** : #8 non supporté |
| AN1 | ABS(-1) = 1 | PRINT ` 1 \n` | **PARTIAL** : #8 non supporté |
| V07 | A%=7, ABS(A%) = 7 | PRINT ` 7 \n` | **PARTIAL** : variable lue, #8 non supporté |
| VN7 | A%=-7, ABS(A%) = 7 | PRINT ` 7 \n` | **PARTIAL** : variable lue, #8 non supporté |
| VMAX | A%=32767, ABS(A%) = 32767 | PRINT ` 32767 \n` | **PARTIAL** : borne haute, #8 non supporté |
| VNMAX | A%=-32767, ABS(A%) = 32767 | PRINT ` 32767 \n` | **PARTIAL** : borne négative, #8 non supporté |
| VMIN | A%=-32768, ABS(A%) = 32768 | aucun résultat simulé | **UNSUPPORTED**, TYPE_UNVERIFIED |
| B07 | A%=7 puis B%=ABS(A%) = 7 | B%=7, valeur exacte | **PARTIAL** : stockage observé ; témoin PRINT #8 non supporté |
| BN7 | A%=-7 puis B%=ABS(A%) = 7 | B%=7, valeur exacte | **PARTIAL** : stockage observé ; témoin PRINT #8 non supporté |
| BMIN | A%=-32768, B%=ABS(A%) : Overflow in 20, ERR=6 | refuse sans mutation, sans CPC ERR | **UNSUPPORTED**, typage résultat inconnu |
| IMIN | ABS(-32768) = 32768 | aucun résultat simulé | **UNSUPPORTED**, TYPE_UNVERIFIED |
| L20 | ABS(-32768) ligne 20 = 32768 | aucun résultat simulé | **UNSUPPORTED**, TYPE_UNVERIFIED |
| EMPTY | ABS() : Syntax error in 10 | refus `BE_UNSUPPORTED` | **UNSUPPORTED**, diagnostic CPC non émulé |
| STRING | ABS("X") : Type mismatch in 10 | refus `BE_UNSUPPORTED` | **UNSUPPORTED**, diagnostic CPC non émulé |
| MULTI | ABS(1,2) : Syntax error in 10 | refus `BE_UNSUPPORTED` | **UNSUPPORTED**, diagnostic CPC non émulé |

Dans les neuf cas utiles, le **résultat numérique local** est un `MATCH` dans le domaine INTEGER16 ; le classement global **PARTIAL** tient à l'absence de transport imprimante natif dans les programmes CPC. Aucun des seize témoins ne justifie une prétention `ABS` complet.

## Stratégie de vérification

Le CTest déjà déclaré `tests/test_basic_abs_token_list.c` garde **16/16 RAM original/repeat et LIST** plus les négatifs lexicaux historiques. Les ajouts B2a couvrent :

- RED de l'ancien exécuteur (PRINT ABS(0/1/-1) refusé) ; GREEN des immédiats 0, ±1, variables 0, ±7, ±32767, affectations 7/−7 et programme natif multiligne A% → PRINT ABS(A%) → B%=ABS(A%) → PRINT B% pour 0, ±7 et ±32767 ; prévisualisation puis commit cohérents et programme inchangé.
- Rejets atomiques de littéral et variable `-32768` en PRINT/affectation ; variable absente ; `ABS()`, `ABS("X")`, `ABS(1,2)` ; suffixe/parenthèse absents/payload tronqué ; capacité sortie trop petite et store saturé.
- Les six autres familles et la CI permanente restent inchangées. GCC/Clang OFF/ON et ASan/UBSan + Xtensa ESP-IDF 5.5.6 BASIC_PROBE/CONSOLE/HW3 doivent être évalués sur **le SHA final**, pas sur un ancien run.
