**Mission :** [issue #216](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/216).

## Provenance et séparation des statuts

| Information | Nature | État à l'ouverture |
|---|---|---|
| \`CLS\` est une entrée du lexique ROM de BASIC 1.1 | désassemblage \`basic.asm\`, entrée \`E6CC\` (\`8A\`) | **ROM_STATIC_ATTESTED** |
| Dispatch de \`CLS\` vers \`C280\`, \`CALL C1E5\`, puis \`CALL &BB6C\` \`TXT CLEAR WINDOW\` | désassemblage \`basic.asm\` | **ROM_STATIC_ATTESTED** |
| \`C1FB\` inspecte \`#\`, valeur de stream, puis \`C1E5\` vérifie la borne \`< 8\` | lecture statique \`basic.asm\` C1E5–C20C ; **hypothèse sur la syntaxe et ses diagnostics** | **ROM_STATIC / CPC_UNVERIFIED** |
| \`CLS\` efface la fenêtre de texte courante et non une palette globale | **hypothèse issue du nom de l'appel ROM**, pas mesure suffisante | **INCONCLUSIVE avant comparaison de captures** |
| Acceptation de \`CLS #0\` / \`CLS #7\`, rejet éventuel \`CLS #8\` | hypothèses à départager en CPC direct | **UNVERIFIED** |
| \`CLS\` C99 native / CYD | absence contrôlée dans \`core/basic_tokenizer.c\` ; \`!CLS\` hôte décrit dans [matrice](BASIC_COMMAND_MATRIX.md) | **NOT_IMPLEMENTED** |

**Ne pas confondre les trois natures de faits :** ROM lue statiquement, observations vraies Caprice32, et interprétation C99/firmware. Les captures et \`ERR/ERL\` ne deviennent \`OBSERVED\` qu'après une acquisition réelle ; l'exécution C99 reste hors mandat. La présente note et le code d'acquisition ne sont **pas** des preuves CPC par leur seule existence.

## Matrice d'acquisition — 14 cas × 2 sessions = 28 captures indépendantes attendues

Sources ASCII exactes : [\`tests/oracles/inputs/j1_21_a/\`](../tests/oracles/inputs/j1_21_a/). Pour chaque cas et répétition, deux **processus CPC** distincts : LIST + snapshot RAM (temporaire), puis deux screenshots avant/après CLS **dans le même processus** ; les répétitions \`original\` et \`repeat\` redémarrent chacune le CPC. Le protocole acquiert **56 processus** minimum (2 × 14 × 2), sans recycler les snapshots comme machine vivante.

| Cas | Action analysée | Variables et témoins | Risque/limite |
|---|---|---|---|
| \`D_FULL\` | \`CLS\` direct | écran MODE1 marqué ; programme témoin \`REM/END\` préexistant | invite et saisie restent visibles |
| \`D_WINDOW\` | \`CLS\` direct | \`OUTSIDE\` imprimé **avant** \`WINDOW 10,30,8,20\`, \`INSIDE\` après | coordonnées \`LOCATE\` relatives à la fenêtre |
| \`D_PAPER\` | \`CLS\` direct | \`PAPER 2\` avant effacement | ne déduit pas une couleur sans RGB |
| \`D_INK\` | \`CLS\` direct | encres redéfinies (\`INK 0,6\`) | pixels dépendants des encres |
| \`D_HASH0\` | \`CLS #0\` direct | présomption de stream texte 0, hypothèse ROM | acceptation/effet à observer |
| \`D_HASH7\` | \`CLS #7\` direct | borne supposée supérieure des streams | effet visuel écran 0 peut être nul |
| \`D_HASH8\` | \`CLS #8\` direct | contre-exemple de borne supposée | diagnostic CPC **non prédéclaré** |
| \`N_FULL\` | \`10 CLS\` puis \`20 END\`, \`RUN\` | écran MODE1 marqué | CLS dans le programme |
| \`N_WINDOW\` | \`10 CLS\` dans la fenêtre active | \`OUTSIDE\` et \`INSIDE\` contrôlés | démontrer la conservation hors fenêtre |
| \`N_PAPER\` | \`10 PAPER 2 / 20 CLS / 30 END\` | PAPER modifié **par programme** | instrumenter palette / fond sans transposer au CYD |
| \`N_MODE0\` | \`10 CLS\`, \`MODE 0\` initial | largeur texte MODE0 | ROI au pixel Caprice32, sans déduire colonnes |
| \`N_MODE2\` | \`10 CLS\`, \`MODE 2\` initial | largeur texte MODE2 | écran/encres distincts |
| \`N_CURSOR\` | \`10 CLS / 20 PRINT "AFTER" / 30 END\` | \`LOCATE 4,4\` avant RUN | **capture après RUN comprend PRINT** : ne pas isoler la seule transition CLS à partir de ce cas |
| \`N_DOUBLE\` | \`10 CLS:CLS / 20 END\` | répétition sur même ligne | deux CLS sont indissociables sans instrumentation |

**Fenêtre, curseur, conservation du programme.** Le \`LIST #8\` imprimante de **pré-RUN** est comparé à celui obtenu **après** les deux captures et \`ERR/ERL\`. Cela teste le programme **stocké**, même dans les cas directs. L'emplacement précis du curseur **n'est pas revendiqué** tant qu'un point de marquage après CLS n'est pas obtenu et isolé de l'écho de saisie/Ready. Le scénario \`N_CURSOR\` teste un marqueur \`AFTER\`, mais sa capture finale intègre ce PRINT ; sa ROI ne prouve pas un CLS isolé.

## Ordre exact du protocole

1. **Préparer chaque processus** : \`MODE {0,1,2}\`, \`INK 0,0\`, \`INK 1,26\`, \`INK 2,6\`, \`INK 3,18\`, \`PAPER 0\`, \`PEN 1\`, \`CLS\`, \`NEW\`. Ce **CLS d'initialisation** est distinct du **CLS cible** et précède toutes les captures. Les commandes supplémentaires propres au cas sont versionnées dans \`capture.json\`.
2. **Processus LIST (ne RUN pas)** : saisir les lignes source ; \`LIST\` ; screenshot \`list/screen.png\` et snapshot \`*.sna\` **temporaire** ; \`LIST #8\` vers \`list/printer.dat\`. Extraire \`program.bin\` via le **lecteur indépendant** \`token_ram_oracle\` ; ne jamais publier ROM ni SNA. Pour \`N_*\`, vérifier dans la ligne appropriée le token ROM \`8A\`.
3. **Processus RUN indépendant** : même setup et lignes, préparer marqueurs visuels, **screenshot avant** \`CLS\` à partir de \`CAP32_DELAY\`; envoyer la cible directe ou \`RUN\` ; **screenshot après**. C'est une vraie chronologie dans **un même processus**, et non la différence artificielle entre deux initialisations CPC.
4. **Après la seconde capture seulement** : \`PRINT #8,ERR\`, \`PRINT #8,ERL\`, \`LIST #8\` ; lire la sortie brute et préserver les bytes. Ce sondage est une **instrumentation post-exécution**, susceptible de modifier le contexte ensuite ; il ne doit pas être confondu avec la capture de l'instruction isolée.
5. Mesurer le screenshot PNG RGB (CRC/chunks lus par \`j1_18_a_ink_pixels.py\`) : ROI rectangle texte \`(64,81,704,481)\`, coin haut gauche \`(64,81,200,161)\`, cœur fenêtre \`(224,201,544,401)\`, bas droit \`(560,401,704,481)\`, bornes de fin **exclusives**. Histogrammes RGB avant/après, nombre exact de pixels changés et SHA RGB des deux images. Les ROIs sont **d'abord des instruments**, pas des preuves que chaque changement est dû au seul CLS (écho, curseur et Ready possibles).
6. **Recommencer depuis zéro** pour \`repeat\`, comparer programme RAM, LIST, \`ERR/ERL\`, mesures ROI, SHA des pixels décodés et horodatages des processus.
