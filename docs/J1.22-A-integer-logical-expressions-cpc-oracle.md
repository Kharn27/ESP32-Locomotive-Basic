## Protocole d'acquisition (non exécuté)

Le script tools/j1_22_a_integer_logical_oracle.py réemploie les modules existants j1_18_a_ink_evidence et token_ram_oracle **sans les modifier**. Il exige checkout Git HEAD complet, base ancêtre, ROM CPC6128 authentique, révision Caprice32 épinglée et exécutable cap32 issu du conteneur GHCR avec xvfb-run.

Pour **chaque cas / chaque session indépendante** :

1. Nouveau processus Caprice32 : MODE 1, NEW, entrée des lignes du programme, LIST sur écran + screenshot, CAP32_SNAPSHOT temporaire, LIST #8 vers imprimante ; extraction des enregistrements RAM depuis le snapshot CPC.
2. **Autre processus Caprice32** : saisie identique, RUN, screenshot de la sortie et des messages CPC, probe séparé PRINT #8 avec sentinelle @@J122ERR@@ et ERR/ERL, puis LIST #8. Le script conserve intégralement les octets imprimante avant la sentinelle comme résultat, pas une reconstruction Python/C99.

Cela représente **24 programmes × 2 sessions = 48 sessions originales/répétées, 96 lancements distincts et 48 snapshots transitoires**, jamais archivés. Pour chaque exécution, conserver source SHA, token RAM program.bin, LIST avant/après, résultat et ERR/ERL, screenshot LIST/RUN, logs bruts, commandes, horodatages et capture.json. Les messages d'erreur sur écran doivent être transcrits à partir des PNG authentiques (ou laissés DIAG_CPC_UNVERIFIED) : ni OCR simulé ni confusion de sorties imprimante et écran.

**Commandes à exécuter seulement dans un environnement d'acquisition Caprice32 autorisé :**

~~~bash
python3 tools/j1_22_a_integer_logical_oracle.py --check-sources --self-test
python3 tools/j1_22_a_integer_logical_oracle.py \
  --acquire tests/oracles/caprice32 \
  --head "$(git rev-parse HEAD)" --output "$RUNNER_TEMP/j122-original"
python3 tools/j1_22_a_integer_logical_oracle.py \
  --verify-unsealed "$RUNNER_TEMP/j122-original"
~~~

Le résultat UNSEALED signifie seulement cohérence interne ; jamais CPC_ORACLE_VERIFIED.
