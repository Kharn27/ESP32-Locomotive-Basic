## Evaluation model

- C99 two-pass native evaluator for CPC tokenized INTEGER16 data, no Z80, heap or global mutable state.
- Explicit INTEGER scalar references only; inline typed comparisons return CPC bit pattern `-1` or `0`. Bitwise operators use `uint16_t` masks and signed conversion by a verified `int32_t` range.
- Parentheses, unary minus, NOT, multiplication, integer division, MOD, addition/subtraction, comparisons, AND/XOR/OR have explicit precedence. No short-circuit: errors inside AND operands reject before output/store commit.
- Parser and emitter enforce finite capacity; result/assignment/cursor/output remain unchanged on failed first pass. Imported malformed tokens are rejected without mutating BASIC program.
- CPC printer `#8` is represented by host PRINT bytes and LF, not a real printer; native statuses are **not** equivalent to CPC `ERR` codes.

## Strict classification

- `MATCH_SEMANTIC`: authentic CPC numeric outcome or IF arm matches native typed-store/PRINT execution; LF host channel remains different from CPC CRLF printer. Requires an actual passing run.
- `MATCH_EXACT`: only when comparing commensurate byte streams, e.g. source and native LIST with expected native token form. **Not** automatically claimed for CPC printer.
- `MATCH_DIAGNOSTIC_CLASS`: both CPC and native stop before assignment/output on the same numeric failure class; the BASIC ERR number is **not** the host enum value.
- `DIFF`: mismatch of native output/result/status or unexpected state mutation.
- `UNVERIFIED`: incomplete run, missing comparison, or CI cancelled / skipped.
- E01 original observed `Division by zero in 10` / `ERR=11, ERL=10`; native returned `BE_DIVISION_BY_ZERO` without modifying assignment/output. E02 original observed `Overflow in 10` / `ERR=6, ERL=10`; native returned `BE_INTEGER_OVERFLOW` without commit. These diagnostic classes do **not** establish equality of numeric CPC ERR and host enum.

All source strings are tokenized via production `bt_tokenize`, listed by production `bl_list_program`, executed by production `be_step`, and observed in typed store or output; there is no case-dependent execution behavior. Explicit negative tokenizer tests cover missing operands, unbalanced parentheses, out-of-range literals, unsupported types and division syntax; executor tests cover insufficient output capacity, missing INTEGER variable, typed STRING operand injection, malformed imported tokens, truncated operators, full store, alias/overlap and atomic failure on arithmetic diagnostics. Independent (non-CPC-oracle) native regression exercises a second variable name (LONG% / OTHER%).
