## Nature et provenance de la preuve

Le pilote tools/j1_23_a_locate_border_oracle.py prépare 20 programmes CPC ASCII distincts. Il n'utilise ni exécuteur natif ni résultat du désassemblage : chaque programme comporte une ligne 10 avec LOCATE ou BORDER, une ligne 20 avec PRINT d'une marque visuelle, et une ligne 30 END. Il fait tourner Caprice32 (commit 8c778bf072a06fb7c23b9cccd179041db7f79a52) sur la ROM CPC6128 BASIC 1.1 SHA-256 31c3668c67bea027dab698ece233c9434d9324f9ba7dac84db58f400b6689562. Image GHCR identifiée par sha256:7c2ac82df92a2df5c7305cc0bd70dc95124249fb46b2d893449f3d48395ced8c. Ces valeurs sont des prérequis vérifiés, pas des preuves d'exécution tant que la capture n'a pas réussi.

Hypothèses lexicales à falsifier sur les octets RAM **capturés**, sans préjuger du résultat : LOCATE = &A9 ; BORDER = &82. Le pilote consigne l'octet effectivement lu dans le record 10, ainsi que le booléen de concordance. Il ne fabrique pas les tokens en Python.

Pour chaque cas, deux sessions distinctes **original/repeat** ; pour chacune, un processus LIST avec snapshot RAM transitoire et LIST #8, puis un autre processus RUN avec PNG avant/après, ERR/ERL via PRINT #8 et LIST #8 final. Les snapshots complets et ROM ne sont jamais archivés. Les tokens restent des extraits réels du programme BASIC, pas du code C99.

## Fichiers et scellement

Chaque cas/session produit **9 fichiers** : program.bin (RAM vraie), capture.json, list/caprice.log, list/screen.png, list/printer.dat, run/caprice.log, run/screen_0.png, run/screen_1.png, run/printer.dat. Total : 40 sessions, 80 lancements Caprice32, **360 fichiers binaires/texte** et un manifeste SHA-256, sans .sna/.rom/.dsk ni INI.

Le vérificateur contrôle l'inventaire, les SHA-256, la structure des lignes RAM, les octets de LIST, les entiers ERR/ERL, les régions RGB, les horodatages distincts et la répétition indépendante. Quatre corruptions de copie RAM/LIST/PNG/manifest doivent être rejetées. Ces contrôles internes ne constituent pas, seuls, un sceau externe. La commande **--external-manifest-sha256** doit recevoir une valeur relevée **indépendamment depuis l'artefact ORIGINAL de CI**. Ne jamais utiliser un SHA calculé depuis le candidat pour prétendre à une attestation externe ; tant que non obtenu, la sortie est UNSEALED et non CPC_ORACLE_VERIFIED.

Le workflow d'acquisition isolé **temporaire** .github/workflows/j1-23-a-locate-border.yml a été utilisé pour le run Actions #41541341285, puis **supprimé de la branche avant la remise** : le garde historique CI-OPT3 refuse à juste titre un nouveau workflow non répertorié. Aucun workflow ni script de routage existant n'a été modifié. Le run original reste consultable via ses logs, SHA et artifact ; la reproduction intégrale requiert un harness éphémère séparé explicitement autorisé par le Pilotage, pas une modification de workflow scellé.
