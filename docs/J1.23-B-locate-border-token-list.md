# J1.23-B — LOCATE + BORDER : tokens CPC et LIST, C99 lexical uniquement

**Ordre Pilotage :** [issue #277](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/277#issuecomment-6598802544).
**Base :** main@cf30fd6235b0a06c36b1a4d0bbea1a841c937485, 6/6 CI post-fusion success attestées.
**Branche :** feat/j1-23-b-locate-border-token-list. **J1.23-C non autorisé**.

## Scope

L'encodage et le LIST inverse concernent uniquement LOCATE=&A9 et
BORDER=&82, lus de la RAM CPC6128 J1.23-A. Deux fichiers CORE sont
modifiés : core/basic_tokenizer.c et core/basic_listing.c.
Aucune API publique, aucun exécuteur, BSR, I/O, HAL, firmware, écran,
HW4 ni archive CPC ne sont modifiés. L'exécution native de LOCATE et
BORDER reste un refus atomique ; aucune position du curseur, couleur
TFT ou cadence de clignotement n'est prétendue.

## Oracle comparé, et non produit par le code C99

Source CPC scellée en lecture seule :
tests/fixtures/cpc6128/j1_23_a_locate_border/{original,repeat}/*/.
Le manifeste a pour SHA-256 externe :
31addf9025214ea4f4f5ea3d8f592cb0cffbfac4c0fd962d2fee9fa30266a1f8.
Les 20 lignes 10 et les lignes 20 PRINT "LBLOC" ou PRINT "LBBOR",
puis 30 END, sont exactement celles du corpus J1.23-A.

Pour chaque témoin et pour chaque session, le nouveau CTest
j1_23_b_locate_border_cpc_lexical reconstruit le programme à partir du
texte figé, exporte son image RAM numérotée complète, compare chaque
octet à program.bin **provenant du CPC**, importe la RAM CPC puis LIST
les deux programmes. Le LIST C99 est comparé aux octets réels
list/printer.dat de la ROM CPC avant RUN ; seul le séparateur CRLF
(imprimante CPC) contre LF (API C99) est normalisé, caractère par
caractère. Le LIST est ensuite retokenisé et réexporté pour comparer
l'image RAM originale. Aucune comparaison ne consulte le LIST après RUN
sur LOCATE 1.

Le statut d'exécution n'intervient ni dans l'acceptation du tokenizer,
ni dans le LIST ; en particulier les cinq cas négatifs exécutifs sont
stockés si l'oracle les stocke. Les deux syntax errors sont imprimées
par LIST pré-RUN selon leurs octets véritables.

Nombres CPC : 0..9 dans 0E..17 ; 10..41 (LOCATE) et 10..27
(BORDER) dans 19,immédiat ; -1 dans F5 0F ; les témoins additifs
sont deux immédiats autour de F4. Seules les combinaisons d'addition
exactement mesurées sont codées. Aucun calcul arithmétique au RUN.
La grammaire accepte le sous-ensemble nécessaire et refuse
expressément les valeurs/expression inconnues hors de ce domaine ;
ne pas extrapoler ces refus comme comportements ROM CPC.

## Négatifs, sûreté et non-régression

Le CTest vérifie en outre les préfixes lexicalement interdits,
tokens tronqués/altérés, absence de place, recouvrement source/buffer,
chaînes et REM opaques adjacents, canaris du buffer et du compteur sur
refus, préservation du programme, et rejet RUN via BE_UNKNOWN_TOKEN
sur les deux instructions sans avancer l'état de l'exécuteur.
Il ne crée ni événements vidéo, ni nouvelles interfaces.

## Reproduction

~~~sh
cmake -S . -B build-j123b -DBUILD_TESTING=ON
cmake --build build-j123b -j2
ctest --test-dir build-j123b -R j1_23_b_locate_border_cpc_lexical -V

cmake -S . -B build-j123b-asan -DBUILD_TESTING=ON -DBP_SANITIZERS=ON
cmake --build build-j123b-asan -j2
ctest --test-dir build-j123b-asan -R j1_23_b_locate_border_cpc_lexical -V
~~~

GCC/Clang, OFF/ON, ainsi que CI-ARCH, OPT3, CPC-PERMANENT,
Xtensa 3/3 et delta mémoire sur HEAD final doivent être
relevés **sur les runs réels** : aucune mention PASS n'est anticipée.
La CI-CPC-PERMANENT **ne surveille pas J1.23-A** et n'est pas
présentée comme telle ; le nouveau CTest lit l'archive immutable.
