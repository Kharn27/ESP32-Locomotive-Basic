# J1.23-C1 — LOCATE + BORDER natifs, effets logiques CORE-ONLY

Mandat : [Issue #280](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/280). Base immuable de développement : `main@e6096fa0ca159c9eda5fa876d0ecf3eb68a7d07f`. Aucun écran, firmware ou moteur de rendu modifié. Cette tranche **ne prétend pas** afficher LOCATE ou BORDER sur CYD. Pilotage seul accepte la PR et la fusionne.

## Contrat des événements, ABI conservée

Les types existants `BE_VIDEO_SET_TEXT_PEN=1`, `BE_VIDEO_SET_INK=2`, `BE_VIDEO_CLEAR_TEXT=3` et `BE_VIDEO_SET_TEXT_PAPER=4` restent inchangés. Deux types sont **appendus** :

| Type | `pen` | `ink` | `colour` | `print_offset` |
|---|---|---|---|---|
| `BE_VIDEO_SET_TEXT_CURSOR=5` | x CPC **1-based** | y CPC **1-based** | 0 (réservé) | Nombre d'octets PRINT précédant LOCATE |
| `BE_VIDEO_SET_BORDER=6` | encre CPC n° 1 | encre CPC n° 2 si présente, sinon 0 | **1** si deuxième argument présent, **0** sinon | Nombre d'octets PRINT précédant BORDER |

Le type de l'événement détermine le sens des champs : **ne jamais lire la position comme une couleur, ni l'encre comme du RGB**. `BORDER 26` → `pen=26,ink=0,colour=0` ; `BORDER 26,0` → `pen=26,ink=0,colour=1`. Aucune confusion possible entre argument optionnel absent et valeur zéro. Les quatre événements précédents conservent intégralement leur contrat.

Pas de nouveau champ, pas de heap : `BEVideoEvent` Xtensa fait toujours **16 octets** (`print_offset=8`, `ink=12`, `colour=13`), contrôlés à la compilation par la vérification `ESP_PLATFORM`; sous hôte 64 bits, taille **24 octets**. Les octets PRINT restent uniquement du texte; LOCATE/BORDER n'en émettent aucun. Les événements sur une même ligne sont ordonnés par `print_offset`.

Le bridge `integration/hw4_pen_bridge.c`, contrôlé **en lecture seule** sur la base, accepte explicitement uniquement PEN/CLS; les nouveaux types provoquent `HW4_PEN_INVALID_EVENT` en prévol de toute la ligne, **avant** le commit du scheduler. L'étape `bsr_preview_step_events` est pure; l'effet matériel est délibérément absent. Les combinaisons existantes PEN/INK/PAPER/CLS ne sont pas modifiées.

**Exception prouvée :** sur L_MISSING, l'écran affiche « Syntax error in 10 », mais l'imprimante sonde `ERR=0`, `ERL=10` et le LIST post-RUN diffère. `ERR=0` **n'est pas** interprété comme un succès. `BE_DIAG_CONTRADICTORY` garde cette anomalie visible, sans inventer un numéro d'erreur CPC. De même, `BE_INVALID_LOCATE`, `BE_INVALID_BORDER` et `BE_OPERAND_MISSING` sont des **causes hôte typées**, jamais les valeurs numériques historiques elles-mêmes. Aucun message CONSOLE ajouté.

L'acceptation `LOCATE 41,1`, `LOCATE 1,26` et `BORDER 27` interdit d'imposer les supposées bornes 40×25 ou 0..26. Les coordonnées hors viewport, la fréquence et l'alternance BORDER, les fenêtres texte, les streams, RGB/TFT et la phase ne sont **pas caractérisés** ici. Toute forme non mesurée retourne `BE_UNSUPPORTED` ou une cause de structure hôte (troncature, séquence), sans prétendre décrire le comportement ROM CPC.

## Atomicité et régression J1.23-B

La sonde `execute_line` s'exécute sans destination, avant tout écrit; `be_step_events`/preview partagent le prévol, les vérifications de place, d'overlap, et le second passage d'émission. Aucun événement, texte, compteur, curseur, programme, variable ou pile ne change en cas de refus.

**Compatibilité lexicale historique :** le test J1.23-B scellé appelle `be_step` (API **sans** destinataire d'événements) sur un premier statement LOCATE/BORDER et attend `BE_UNKNOWN_TOKEN`. Le wrapper legacy préserve *uniquement* ce statut d'absence d'exécution, sans produire d'effet. Le nouveau `be_step_events` retourne à la place `BE_EVENT_RECEIVER_REQUIRED`, permettant au client typé d'identifier la dépendance au récepteur. Le wrapper `bsr_step` utilise lui aussi le chemin typé avec récepteur absent et renvoie `BE_EVENT_RECEIVER_REQUIRED`, contrairement à l'API directe `be_step`. Pour un programme mixte commençant par PRINT, le legacy retourne aussi `BE_EVENT_RECEIVER_REQUIRED`. Le CTest ancien n'a pas été modifié.

Le nouveau CTest couvre les 20 cas × original/repeat, diagnostics distincts, `be_step`, récepteur absent, répétition preview puis commit, capacité d'événements 0/1/2, PRINT et offsets, canaris, programme/stores/call/FOR inchangés sur refus, données corrompues/tronquées/non mesurées, ABI host/Xtensa. Le bridge HW4 n'est ni testé physiquement ni modifié.
