# J1.24-A — Oracle CPC6128 indépendant WHILE/WEND

**Mandat :** [#284](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/284) ; démarrage depuis `main@355b9bd67ba8970abafcf67978854cebcb878273` ; branche `oracle/j1-24-a-while-wend-cpc`. **Acquisition seule** : aucun tokeniseur, `LIST` natif, exécuteur C99, runtime CORE, firmware ou HW4 ne fait partie de cette tranche.

## Questions expérimentales, pas résultats CPC

Les 20 programmes ASCII ci-dessous sont écrits littéralement dans `tools/j1_24_a_while_wend_evidence.py`, dictionnaire `CASES`. Le fichier est la source normative intégrale ; chaque programme est composé de lignes BASIC numérotées et finit par `END`. Les noms décrivent les intentions d'essai ; **ils n'annoncent pas les réponses de la ROM**. Aucun token, résultat, ERR/ERL ni sortie attendue n'est injecté dans le collecteur.

| Cas | Condition / structure | Question à trancher |
|---|---|---|
| ZERO_LITERAL | `WHILE 0` | Bloc écarté dès l'entrée ? |
| FALSE_REL | `A%=0: WHILE A%<0` (sur lignes différentes) | Relation INTEGER fausse au départ ? |
| ONCE_LT | `A%=0; WHILE A%<1; A%=A%+1` | Un seul tour et sortie ? |
| THREE_LT | `A%=0; WHILE A%<3; A%=A%+1` | Plusieurs tours ? |
| GT_DECREMENT | `A%=3; WHILE A%>0; A%=A%-1` | Décrément et sortie ? |
| LE_BOUNDARY | `A%=0; WHILE A%<=2` | Frontière inclusive ? |
| NE_EXIT | `A%=0; WHILE A%<>2` | Sortie sur égalité ? |
| EQ_FALSE | `A%=1; WHILE A%=0` | Égalité fausse ? |
| EQ_ONCE | `A%=1; WHILE A%=1; A%=2` | Égalité initialement vraie puis fausse ? |
| GE_DECREMENT | `A%=2; WHILE A%>=0` | Frontière zéro avec descente ? |
| NEST_2X2 | `WHILE A%<2` contenant `WHILE B%<2` | Ordre d'exécution de boucles imbriquées ? |
| NEST_SKIP_INNER | `WHILE A%<2` contenant `WHILE B%<0` | Corps intérieur sauté ? |
| WEND_ORPHAN | `WEND` isolé | Diagnostic exact et ligne ? |
| WHILE_UNCLOSED | `WHILE 0` sans `WEND` | Correspondance structurelle manquante ? |
| WHILE_MISSING | `WHILE` sans condition | Diagnostic de syntaxe ou opérande ? |
| WEND_OPERAND | `WEND 1` | Opérande supplémentaire, acceptation ou refus ? |
| WHILE_BAD_REL | `WHILE A%<` | Relation incomplète, diagnostic ? |
| COLON_SAME_LINE | `A%=0:WHILE...:PRINT...:A%=...:WEND` | Sémantique des délimiteurs sur une ligne ? |
| COLON_CROSS_LINE | `WHILE ...:PRINT` et `A%=...:WEND` | Correspondance sur deux lignes mixtes ? |
| EMPTY_BODY | `WHILE A%<0` puis `WEND` immédiat | Bloc vide, sortie ? |

Les PRINT vers `#8` sont des **marqueurs de RUN mesurés**. Leur fréquence, leur ordre et leur absence sont archivés comme octets observés, **jamais présumés**. Pour les programmes utilisant un compteur, les incréments/décréments visent des sorties finies ; si la ROM ne les exécute pas comme envisagé et dépasse la limite de processus (90 s), l'essai **échoue**. Pas de boucles de sortie infinies volontairement introduites.

## Protocole d'observation

Caprice32 `8c778bf072a06fb7c23b9cccd179041db7f79a52` ; ROM CPC6128 Locomotive BASIC 1.1 SHA-256 `31c3668c67bea027dab698ece233c9434d9324f9ba7dac84db58f400b6689562` ; image GHCR `sha256:7c2ac82df92a2df5c7305cc0bd70dc95124249fb46b2d893449f3d48395ced8c`. L'outil `j1_18_a_ink_evidence.py` sert **uniquement** de contrôleur et de lanceur Caprice32 existant, avec `subprocess.run(...,timeout=90)` : aucune exécution C99 du BASIC. Acquisition dans un conteneur Actions avec submodule Caprice32 épinglé et binaires/ROM authentifiés.

**Chaque session** : un processus Caprice32 `LIST` (sauvegarde transitoire du snapshot pour extraire les **records BASIC réels**, `LIST #8` et PNG), puis un **nouveau** processus `RUN` (capture PNG avant/après, sortie imprimante des programmes, message-sentinelle `J124_DIAG_BEGIN`, `PRINT #8,ERR`, `PRINT #8,ERL`, `LIST #8`). Deux sessions `original/repeat` indépendantes par cas ; **40 sessions, 80 processus** quand l'acquisition a réellement réussi.

Le parseur sépare dans `run/printer.dat` : octets imprimés **avant la sentinelle** (résultat RUN), deux lignes numériques après (sondes ERR/ERL) puis `LIST #8` post-RUN ; leur taille, contenu et SHA sont archivés séparément dans `capture.json`. Ne pas confondre le marqueur de sonde avec un texte émis par la boucle. Les sorties `ERR=0` restent `NOT_INFERRED_FROM_ERR_ZERO`; pour la cause et le texte exact de l'erreur écran, consulter le PNG de RUN. En l'absence de lecture visuelle indépendante, noter `PENDING_MANUAL_SCREEN_INSPECTION` et **UNVERIFIED**, conformément au gate #195. Les variations d'écran mesurées par SHA/ROI n'établissent pas à elles seules l'erreur affichée.

La ROM et les snapshots complets restent hors archive. Par cas/session, exactement **9 fichiers** : `program.bin`, `capture.json`, `list/caprice.log`, `list/screen.png`, `list/printer.dat`, `run/caprice.log`, `run/screen_0.png`, `run/screen_1.png`, `run/printer.dat`. Un manifeste liste leurs 360 SHA-256, le SHA du commit d'acquisition, la version de Caprice32 et l'identifiant de run. Aucun résultat de code source C99 natif n'est utilisé comme oracle.

## Scellement, vérification indépendante et contrôles négatifs

La commande `--acquire` écrit un manifeste `status=UNSEALED`. Le message `CAPTURE_40_MANIFEST_SHA256` est imprimé durant le run réel, **avant tout commit de l'archive**, et sert à relever un ancrage externe. Une vérification **distincte** doit relire les 360 fichiers effectivement versionnés sur GitHub, recalculer leurs hashes depuis les octets, comparer `original/repeat`, vérifier les processus et appliquer un `--external-manifest-sha256` qui **ne doit pas être récupéré du manifeste en cours de validation**. Les falsifications RAM, LIST, sortie/sonde et manifeste doivent être rejetées pour la cause attendue ; un HASH interne non ancré ne suffit pas contre la falsification coordonnée.

Avant acquisition, `--check --self-test` valide uniquement les **questions sources et le fail-closed**. Ce n'est **ni** une preuve de 40 sessions, **ni** `CPC_ORACLE_VERIFIED`. Après acquisition et contrôle externe réussi, le verdict peut être borné aux 20 cas réellement scellés. Des erreurs d'outil, d'export, de screenshot, un timeout, une acquisition manquante ou un fichier symlink provoquent un **FAIL fermé**, jamais un faux PASS.

```sh
python3 tools/j1_24_a_while_wend_evidence.py --check --self-test
python3 -m unittest discover -s tests -p 'test_j1_24_a_while_wend_oracle.py' -v
# Dans le runner authentifié uniquement :
python3 tools/j1_24_a_while_wend_evidence.py --acquire tests/oracles/caprice32 --output /tmp/j124a --head <HEAD_ACQUISITION>
python3 tools/j1_24_a_while_wend_evidence.py --verify /tmp/j124a --self-test
# Après scellement externe :
python3 tools/j1_24_a_while_wend_evidence.py --verify tests/fixtures/cpc6128/j1_24_a_while_wend --external-manifest-sha256 <SHA_DU_RUN_ORIGINAL> --self-test
```
