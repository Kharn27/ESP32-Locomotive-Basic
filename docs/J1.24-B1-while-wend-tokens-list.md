# J1.24-B1 — WHILE/WEND : tokens et LIST CPC natifs (sans RUN)

**Mandat :** [Issue #290](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/290). Base vérifiée GitHub : `main@6727c4102d8cc1413386e01325c096eb3e0511a2`. Branche `feat/j1-24-b1-while-wend-tokens-list`. **B2 reste bloqué.**

## Portée

Seulement `core/basic_tokenizer.c`, `core/basic_listing.c`, `tests/test_j1_24_b1_while_wend_token_list.c`, inscription additive CMake et présent rapport. Aucun changement d'exécuteur, store, runtime, firmware, matériel, workflow ou historique CPC.

L'oracle CPC6128 Locomotive BASIC 1.1 **J1.24-A** a effectivement observé en RAM des records `WHILE=D6` et `WEND=D5`, avec cache opaque `02 00 00 C1` pour `A%`, `02 00 00 C2` pour `B%` et opérateurs relationnels `EE` (>), `EF` (=), `F0` (>=), `F1` (<), `F2` (<>), `F3` (<=). Tokens et payloads ne proviennent pas du désassemblage ou du programme C99 : ils sont testés octet par octet contre les records de `tests/fixtures/cpc6128/j1_24_a_while_wend`, `original` **et** `repeat`.

Le tokenizer encode la condition INTEGER en réutilisant la grammaire **existante** d'INTEGER relationnel et de références BVR, bornée par `:` ou fin de ligne ; cela ne crée pas d'évaluateur. Trois anomalies syntaxiques restent **stockables** dans le corpus : `WHILE` sans condition, `WHILE A%<` à opérande manquant et `WEND 1`. `WEND` orphelin et `WHILE` sans `WEND` n'ont aucune restriction lexicale supplémentaire. Deux formes avec deux-points (`COLON_SAME_LINE` et `COLON_CROSS_LINE`) comprennent exactement `PRINT #8,"C"` après WHILE ; cette forme est limitée aux témoins de J1.24-A, pas une extension générale de `PRINT #8`.

Le `LIST` inverse lit les caches BVR comme des records opaques (jamais interprétés comme commandes), rétablit les mots-clés et les opérateurs. Les décodeurs sont *bornés* et la double passe de validation/écriture garantit l'atomicité des tampons sur échec.

## Oracle immuable : protocole de correspondance

Pour les 20 programmes et les deux sessions :

1. Le test relit `program.bin` **authentique** via `bp_import`, puis la capture `list/printer.dat` **pré-RUN**, jamais `run/printer.dat` ni `LIST` après RUN. Il confronte la source exacte du cas à la sortie imprimante CPC avec CRLF (le `LIST` hôte utilise LF).
2. Il retokenise **uniquement les lignes portant WHILE/WEND** ; chacune est confrontée au record original **entier** : longueur, numéro de ligne, token, expression, cache BVR et NUL final. Aucune fabrication ou correction de cache. Les records originaux et répétés doivent être bit-identiques.
3. Il vérifie `bl_detokenize` à partir des octets CPC, puis retokenise le texte natif pour vérifier un aller-retour strict. Les lignes de `PRINT #8` hors WHILE/WEND restent **hors comparaison de tokenisation native**, puisque l'objectif B1 n'autorise pas l'élargissement de ces commandes ; il ne faut **pas** confondre cette projection avec une égalité native de l'intégralité du programme.
4. Les formes invalides à RUN sont néanmoins vérifiées au niveau stockage/LIST. `WEND_OPERAND` garde strictement le statut historique `DIAG_CONTRADICTORY` : CPC affiche **`Syntax error in 20`**, sonde imprimante `ERR=0 / ERL=20`, et `LIST` post-RUN divergent. **Aucun nouveau code ERR CPC ni fausse réussite.**

Oracle historique **en lecture seule** : [acquisition #41624453081](https://github.com/Kharn27/ESP32-Locomotive-Basic/actions/runs/41624453081), [audit #41626454051](https://github.com/Kharn27/ESP32-Locomotive-Basic/actions/runs/41626454051), scellement externe du manifeste : `11b8450e0d8d772e9c4049aabb78ae2cf32595d7764199fa3904cbc0ba2ca441`.

## Gardes et absence d'exécution

`WHILE` et `WEND` ne sont **pas reconnus comme actions** par `core/basic_executor.c`. L'exécution native est délibérément **non supportée** et doit retourner un refus hôte sans modifier le programme, le curseur, les piles, le store, les buffers PRINT, les compteurs ou les événements. Les essais dédiés couvrent aussi `WHILE 0`, `WEND` orphelin, `WEND 1` et la ligne `A%=0:WHILE...:WEND`.

Tests négatifs : mots-clés préfixes d'identifiants, opérandes non oraclés, `:` malformés, chaînes/REM opaques, tokens tronqués, chevauchements, capacité insuffisante, NULL, absence de modification atomique des sorties et du programme. Aucune extrapolation du code diagnostique hôte vers `ERR/ERL` CPC.
