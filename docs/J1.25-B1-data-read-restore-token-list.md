# J1.25-B1 — DATA / READ / RESTORE : tokens CPC et LIST exacts

**Mandat** : [#321](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/321). Base vérifiée : `origin/main@3a876f980b7632bc92a971a47dc33de49543b8fe` (après CLK-01 #320), gate de départ 6/6 `push:main` SUCCESS documenté dans #321.

## Protocole / frontière

- **Source de vérité indépendante** : `tests/oracles/inputs/j1_25_a/*.bas` pour les douze sources littérales, `tests/fixtures/cpc6128/j1_25_a_data_read_restore/{original,repeat}/CASE/program.bin` pour les **records CPC complets**, et `.../list/printer.dat` pour le **LIST pré-RUN** des 24 sessions. Le corpus et ses empreintes demeurent inchangés ; aucun octet n'est remplacé par ce rapport.
- Le CTest `j1_25_b1_data_read_restore_token_list` crée chaque programme via `bt_tokenize` + `bp_put` + `bp_export`, compare **toute** l'image (longueurs, records, terminateurs `00 00`) à chacun des 24 binaires CPC avec `memcmp`, puis détokenise avec `bl_list_program`.
- **Seule normalisation** : sur le canal **LIST imprimante**, chaque paire de transport `0D 0A` (CRLF) est convertie en `0A` (LF), sans changement d'espace, de token, de ponctuation, de contenu ni de nombre de lignes. Un CR hors CRLF est refusé. Les bytes normalisés doivent correspondre **exactement** au `LIST` natif et au fichier source. `TYPE_MISMATCH` utilise **le LIST pré-RUN**, jamais `list_after_hex` modifié par l'éditeur CPC.
- `LIST` → source → `bt_tokenize` → image RAM : **exact sur le corpus original/repeat**. Aucun claim hors des douze témoins.
- `DATA=8C` laisse les chiffres / guillemets / virgules en texte ASCII ; `READ=C3` encode les références typées `02` INTEGER et `03` STRING avec deux caches 00 et nom terminal bit 7 ; `RESTORE=C7` sans paramètre ou avec cible 100 `1E 64 00`. `PRINT #8` est encodé lexicalement dans les seuls témoins nécessaires, **sans flux d'impression natif**.
- Les chemins `core/basic_executor.*` et `core/basic_session_runtime.*` restent inchangés, et un test exige que les nouveaux tokens soient **rejetés par l'exécuteur existant sans mutation ni sortie**. `TOKEN_LIST_VERIFIED != NATIVE_EXECUTION`, B2 non autorisé.

## Matrice oracle CPC vs programme C99

Dans chaque entrée, la colonne **C99 HEX** désigne exactement la suite affichée pour CPC ; l'identité complète est la condition `memcmp(host, oracle, length)==0` du CTest (et non une simple équivalence visuelle). Les empreintes SHA-256 sont celles des captures scellées, et non de nouveaux fichiers CPC générés.
