## Solution future à campagne unique, sans CI parasite

Après **GO d'exécution explicite du Pilotage sur SHA V2 exact**, le développeur exécutera sur un poste contrôlé disposant de Git, Docker, réseau GitHub et ESP-IDF dans l'image *un lancement manuel local hors GitHub Actions*. Aucun commit ni PR n'est requis pour ce lancement ; aucun nouveau run GitHub n'est initié par la commande, contrairement à l'événement PR. Préconditions : clone propre sur **la branche V2 et son SHA approuvé**, main GitHub encore M2, PR #330 inchangée, `GH_TOKEN` en lecture seule, Docker image exacte, dossier de sortie vierge, budget préalablement autorisé par écrit. Exemple **documentaire NON AUTORISÉ EN C1, À NE PAS EXÉCUTER MAINTENANT** :

~~~sh
export GH_TOKEN=...              # jeton read-only, jamais dans Docker
export E1_PILOTAGE_GO=E1_M2_APPROVED_4_BUILDS  # UNIQUEMENT après GO Pilotage
python3 tools/ci/j125_b2_e1.py --run \
  --approved-head FULL_40_HEX_SHA_V2_APPROVED_BY_PILOTAGE \
  --out reports/j125-e1-local
~~~

La commande `--run` refuse **avant toute sortie/build** les environnements GitHub Actions, l'absence du marqueur GO et un SHA d'autorisation invalide. Elle vérifie via API main M2/PR330/branche V2 et les arbres, le vrai Git `merge-tree --write-tree M2 H` sans conflit, crée un commit temporaire C2 aux parents ordonnés (M2,H), crée des worktrees détachés distincts, et contrôle de nouveau l'API avant et après la campagne. Le lien GitHub `merge_commit_sha` n'est jamais la source du candidat. Docker est épinglé à `espressif/idf@sha256:bf72fe7a15c22849a9a94147301165a545fb8905d97c176cf748e3e4614cac84` (ID attendu `sha256:b5ed7387fed7f3c0cc613272ee7dedab5dddfac6f771ee66af41d93f8d46c0bc`) et n'obtient aucun secret, pour **une seule séquence** M2/SPI40, M2/SPI20, C2/SPI40, C2/SPI20. Aucun B/H rebuild, aucun retry/5e cellule. Le compteur de tentatives et les preuves partielles sont archivés même en échec.

Sur les quatre vrais ELF/BIN : IRAM `.iram0.*` sans le marqueur `.iram0.text_end` de 1 octet, `.iram0.text` distinct, DRAM `.dram0.*` incluant BSS, `.flash.text`, `.flash.rodata`, taille BIN et SHA256. Seul M2→C2 peut recevoir un verdict positif si IRAM=0, DRAM=0, BSS non croissante, DRAM absolue ≤54 864, parité SPI40/SPI20 et BIN différents, sur options identiques. **Limite démonstrative :** la campagne locale n'est pas GitHub Actions et exige un opérateur et un runner local aptes à Docker ; aucun essai sur ce poste, aucune image ni aucun temps mémoire ne sont revendiqués en C1.
