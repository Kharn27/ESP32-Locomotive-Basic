# J1.25-B3 — READ STRING scalaires et mixte INTEGER/STRING (CORE C99)

**Mandat :** [Issue #362](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/362) ; dépendance d'ouverture A4 [#360](https://github.com/Kharn27/ESP32-Locomotive-Basic/pull/360) satisfaite par le Pilotage le 10/11/2026. Branche `feat/j1-25-b3-data-read-string` créée depuis le vrai `main@745003e3850f3fe4529db2541806ec5c07cfbb04` (squash A4). La dette A4-C2 [#364](https://github.com/Kharn27/ESP32-Locomotive-Basic/issues/364) est indépendante de B3 ; aucun REAL5/TIME réutilisé.

## Périmètre strict

- `DATA "HELLO"` + `READ A$`, `DATA "A,B"` + `READ A$`, `DATA 3,"Z"` + `READ A%,B$`. INTEGER B2 inchangé : lecture en ordre source, curseur record/item, `RESTORE` et `RESTORE 100`, saut `GOTO`, `DATA ... : PRINT`, `RUN/NEW/STOP`. Les guillemets délimitent un champ ; la virgule interne ne sépare pas. INTEGER toujours décimal positif 0..32767.
- `PRINT #8,A$` / `PRINT #8,B$` depuis le magasin existant, sans supposer un modèle général de périphérique `#8` ni inventer des espaces. Aucune modification des diagnostics CPC. `BE_UNSUPPORTED`, `BE_TRUNCATED`, `BE_DATA_EXHAUSTED` et `BE_STORE_FULL` sont des causes **internes C99**, jamais des codes ERR/ERL CPC.
- Aucun champ implicite libre, guillemets échappés, caractères de contrôle, expression, REAL5, variable tableau, entrée directe `READ`, ou combinaison DATA avec WHILE. Le rejet antérieur DATA/WHILE et les huit frames WHILE sont inchangés.

## Transactions bornées

1. Un parser pur `data_scalar_item` reconnaît soit le champ cité imprimable ASCII, soit le nombre entier B2. Il retourne un span `offset/length` vers le programme immutable, pas une allocation ou une nouvelle copie. `data_next_scalar` reprend **le curseur B2** sur plusieurs lignes, sans écriture sur l'exécuteur tant que toute la ligne READ n'est pas vérifiée.
2. Avant toute émission de sortie ou mutation, `READ` décode les deux destinations maximales et leurs types, rejette doubles cibles et combinaisons hors corpus, vérifie le type de chaque champ et la disponibilité du second champ. Le préflight du pas vérifie la capacité **totale** des entrées manquantes et appelle `bvs_can_assign_string` pour chaque STRING, y compris longueur / slot fixe / validation d'alias et octets.
3. Les deux passes `execute_line` doivent fournir les mêmes clés, valeurs, offsets, longueurs et curseurs. Uniquement ensuite, `bvs_assign` et `bvs_assign_string` (slot caller-owned) s'exécutent ; tous leurs échecs possibles ont été vérifiés **avant** le premier commit. Le curseur DATA et les compteurs sont écrits après cette séquence. Le tampon/compteur OUTPUT reste intact en cas d'erreur avant ces deux passes. Aucun second curseur ou tampon global n'est ajouté ; la taille de `BasicExecutor` reste inchangée.
4. La garantie d'atomicité suppose le contrat immuable et sérialisé du programme et du magasin entre les deux passes (même contrat que B2 et `be_preview_step_events`). Aucune nouvelle API multi-commit générique ni rollback LCD fictif.

## Oracle CPC6128 réellement acquis

Sources **immuables** `tests/oracles/inputs/j1_25_a/`, captures `tests/fixtures/cpc6128/j1_25_a_data_read_restore/{original,repeat}/CASE/run/printer.dat` (manifest J1.25-A), après suppression **uniquement** des CR de CRLF et du postambule diagnostique `J125_DIAG_BEGIN` (ERR/ERL 0/0 et LIST). Le CTest B3 relit et compare les octets du fichier source authentique et les sorties RUN authentiques, et vérifie aussi la sortie attendue :

| Cas original et repeat | Programme authentique | RUN après CRLF→LF |
|---|---|---|
| ONE_STRING | `DATA "HELLO"; READ A$; PRINT #8,A$` | `HELLO\n` |
| QUOTED_COMMA | `DATA "A,B"; READ A$; PRINT #8,A$` | `A,B\n` |
| MIXED_TYPES | `DATA 3,"Z"; READ A%,B$; PRINT #8,A%; PRINT #8,B$` | ` 3 \nZ\n` |

Ces **6 traces RUN indépendantes** ne prouvent ni la sémantique générale de DATA ni le rendu LCD du CYD. Le CPC `TYPE_MISMATCH` est scellé avec `Syntax error in 10` ; il n'est **pas** corrigé par B3 et aucun diagnostic différent n'est fabriqué.
