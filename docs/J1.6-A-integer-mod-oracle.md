## Acquisition

Les 12 sources LF, `10 A%=n` / `20 B%=A% MOD d` / `30 PRINT B%` / `40 END`, se trouvent dans `tests/oracles/inputs/j1_6_a/`.

Par cas, **deux processus CPC6128 BASIC 1.1 frais** : LIST + screenshot et snapshot temporaire *avant RUN* ; puis RUN dans un autre processus, screenshot **avant** `PRINT #8,ERR` et `PRINT #8,B%`, et imprimante brute distincte. Le snapshot SNA complet est détruit, seul le `program.bin` borné avec longueurs, données de ligne, caches opaques et `00 00` final est conservé. Un `B%=0` post-erreur ne prouve pas l'atomicité CPC.

Le token de `MOD` est **mesuré en RAM** entre le cache source A% et le littéral RHS, sans opcode prédit. Manifestes/sceaux SHA-256 portent la provenance checkout mesurée, le commit Caprice32 `8c778bf072a06fb7c23b9cccd179041db7f79a52`, la ROM historique hashée `31c3668c67bea027dab698ece233c9434d9324f9ba7dac84db58f400b6689562`, et distinguent image PNG, imprimante et stdout C99.

Le workflow `.github/workflows/j1-6-a-mod.yml` épingle le container GHCR, **sans installer ni recompiler Caprice32** ; il archive une fois les authentiques, puis réacquiert et compare les 12 `program.bin` et 12 `printer.dat` octet-à-octet. La permanence et **13 falsifications + faux checkout** sont vérifiées par `python3 tools/j1_6_mod_verify.py --permanent --self-test`. Toute divergence arrête le pipeline : on ne fabrique pas de réponse attendue.
