## Source et matrice

Chaque fichier `tests/oracles/inputs/j1_8_a/<id>.bas` contient exactement les cinq lignes `10 A%=...`, `20 B%=...`, `30 C%=A%-B%`, `40 PRINT C%`, `50 END` avec LF final. Les douze hypothèses pré-CPC sont :

| Cas | A% | B% | Hypothèse, non prouvée CPC |
|---|---:|---:|---|
| P2_P3 | 2 | 3 | -1 |
| P7_N2 | 7 | -2 | 9 |
| N7_P2 | -7 | 2 | -9 |
| N7_N3 | -7 | -3 | -4 |
| NMIN_N1 | -32768 | -1 | -32767 |
| NMIN_Z | -32768 | 0 | -32768 |
| PMAX_Z | 32767 | 0 | 32767 |
| PMAX_N1 | 32767 | -1 | débordement à mesurer |
| NMIN_P1 | -32768 | 1 | débordement à mesurer |
| P255_P255 | 255 | 255 | 0 |
| Z_Z | 0 | 0 | 0 |
| P1_N1 | 1 | -1 | 2 |

La table désassemblée à l'adresse Z80 `D059` répertorie l'opérateur `-` par `F5`, mais **F5 dans la RAM des programmes de cinq lignes n'est pas encore attesté par l'oracle**. L'acquisition relève librement le token et les références C%, A%, B% avec leurs deux octets cache opaques, les tailles et marqueurs des cinq enregistrements et la sentinelle finale `00 00`. Les résultats numériques et l'ERR réel sont observés par `PRINT #8,ERR` et `PRINT #8,C%` après capture écran RUN ; cette sonde ne prouve pas l'atomicité CPC.

## Protocole reproductible

La chaîne `tests/oracles/j1_8_sub_vars_oracle.py` réutilise le processus Caprice32/ROM authentique du banc J0.24 (digest GHCR épinglé dans le workflow). Pour chaque cas elle lance deux processus CPC indépendants, le premier pour saisir les cinq lignes, LIST/PNG et extraire la zone RAM pré-RUN, le second pour saisir de nouveau le même programme, RUN/PNG puis impression sur canal `#8` ; elle archive traces, commandes et originaux. Le script refuse toute déclaration de checkout `GITHUB_HEAD_SHA` différente du véritable `git rev-parse HEAD`. Le C99 actuel est sondé séparément ; `UNSUPPORTED` n'est pas forcé.

L'archive d'origine doit être écrite **une seule fois** sous `tests/fixtures/cpc6128/j1_integer_sub_vars/` par le job GHCR dédié : `program.bin`, `list.png`, `run/run.png`, `run/printer.dat`, journaux, originaux, manifeste et `seal.json`. ROM, images SNA entières et binaires Caprice32 sont interdits. Un nouveau run sur la PR ne réécrit pas l'archive : il effectue `cmp` sur les douze images RAM **et** les douze imprimantes, cas par cas.

**Barrière de scellement :** les douze SHA RAM et le SHA du manifeste doivent être extraits de la première acquisition réellement archivée puis immobilisés dans `tools/j1_8_sub_vars_verify.py`, à partir de leur lecture indépendante. En l'absence de ces 13 constantes, `--permanent --self-test` refuse de passer. L'archive initiale ne constitue donc pas, à elle seule, un jalon livré.

Les tests C99 Linux OFF/ON, Xtensa et les validations HW4 sont des contrôles distincts de l'authenticité de la preuve CPC.
